## 확보 방법과 범위

원본 HTML의 SHA-256은 `aa13c667ba78f914b67d7232aa389469e91d3c582d3c8fe5a166281821f2b1cd`다. 원본은 작업 당시 `/tmp/ai-engineer-roadmap.html`, 해석한 객체는 `/tmp/ai-engineer-roadmap-decoded.json`에 두었다. 임시 파일은 영구 보존을 보장하지 않는다. 본 기록은 내용 전체의 복제본이 아니라 대조 결과이며, 향후 페이지 변경 시 새로 확보해 검토해야 한다.

객체의 생성 시각은 `2025-05-14T10:07:03.713Z`, 갱신 시각은 `2026-08-17T08:12:43.850Z`다. 해당 시각은 페이지 내부 메타데이터이며 집필자가 그 시점의 서비스 상태를 별도로 확인했다는 뜻이 아니다.

화면 구성 요소는 279개다. 이 중 주제 22개, 하위 주제 167개가 있으며 나머지는 라벨·구획·선·버튼 등이다. 따라서 ‘279개 기술’로 표현해서는 안 된다. 명시적 연결은 41개이며 모든 양 끝 식별자가 실제 구성 요소를 참조하고, 구성 요소 식별자의 중복은 없음을 검사했다.

## 연결 해석

명시적 연결에는 소개에서 모델 활용으로, 임베딩에서 모델과 저장소로, 안전에서 평가 영역으로 이어지는 흐름이 있다. 한편 영역 라벨을 향하는 연결과 별도의 선 요소도 있어 모든 연결을 선수 과목의 방향으로 읽을 수 없다. 기획안의 장 순서는 이 도표의 위상 정렬 결과라고 주장하지 않는다.

책에서는 도구의 실행 계약을 먼저 만든 뒤 MCP로 연결한다. 평가 개념은 앞 장의 작은 실험에서 먼저 사용하고 후반에 평가 체계로 종합한다. 안전성도 끝에서 처음 도입하지 않고 데이터·문서·도구의 경계마다 적용한다. 이 재배치는 저자의 학습 설계다.

## 새 범위의 1차 자료 확인

[MCP 2025-11-25 아키텍처 명세](https://modelcontextprotocol.io/specification/2025-11-25/architecture)는 호스트가 클라이언트를 관리하고 클라이언트가 서버와 연결하는 역할 분리를 설명한다. 11장의 구조 설명에 사용할 기준 자료로 확보했다. 전송·권한 명세와 Python SDK 버전은 실습 집필 전에 별도로 검증한다. 이 명세 버전을 현재 최신 버전이라고 단정하지 않는다.

## 남은 한계

현재 확인은 내장 객체와 명시적 연결의 검토다. 렌더링된 도표의 선·박스까지 포함한 시각적 대조와 모든 하위 항목 설명 페이지의 기술 검증은 아직 수행하지 않았다. 제품 이름이 노드에 존재한다는 사실은 제품 기능·지원 상태가 검증되었다는 뜻이 아니다. 장별 공식 문서 조사와 코드 실행은 별도로 수행한다.
