# 정리 모음 — 여러 글을 한 편으로 합칠 때

짧은 글이 쌓이면 주제별로 묶어 한 편으로 만든다. 총량은 그대로지만 페이지당 밀도가 올라간다.

### 묶는 기준

**관통하는 축이 있어야 한다.** 축 없이 나열하면 긴 목록글이 되고, 그건 짧은 글 여러 편보다 나을 게 없다.

- 원리 하나에서 파생되는 사례들 (JSX 중괄호 → 개행·map·onPress·`&&`·컴포넌트)
- 작업하다 순서대로 마주치는 것들 (레이어 겹치기 → position → z축 → 고정 → SafeArea → 제스처)
- 라이프사이클 단계별 실패 (Harbor → 기동 → login → push → pull)

축이 안 나오면 합치지 않는다. 억지로 묶는 대신 개별 확장이나 `noindex`를 택한다.

### 날짜

- 파일명 날짜는 **묶음에서 가장 최근 글의 날짜**를 쓴다. 정리 모음이라는 성격에 맞고, 오래된 내용에 새 날짜를 박으면 본문과 어긋난다
- `last_modified_at`은 정리한 날로 찍는다. `astro.config.mjs`가 이걸 읽어 sitemap `lastmod`로 넣으니 크롤러에는 갱신으로 전달된다
- **각 절 도입에 원래 시점을 적는다.** `2022년 10월, 화면에서 이리저리 끌고 다닐 수 있는 버튼을 붙이면서 알게 됐다`
- 낡은 해법을 현재 기준으로 교체하는 경우에만 예외로 새 날짜를 쓸 수 있다

`PostLayout.astro`는 `modified > date`일 때만 발행일 옆에 `Updated`를 함께 노출한다.

### 원글을 옮길 때

- **1인칭 삽질 서술은 살린다.** 요약해서 지우면 독창성이 사라진다
- **원글의 진단이 틀렸으면 기전대로 다시 쓴다.** `i += 2`에서 `=`를 뺀 코드를 원글은 "문법 오타"로 적었지만
  문법은 맞고 무한 루프였다. 원글 결론("문법이 틀린 게 없나 살펴본다")대로는 그 버그를 못 찾는다
- **진단을 고쳤으면 그 절의 다른 문장까지 같이 맞춘다.** 위 사례에서 기전은 고쳤는데
  원글의 `설마 이런 걸 안 잡아주리라고는 생각하지 않았다`가 그대로 남아, 파서가 잡을 게 없다고
  방금 설명하고서 안 잡아줬다고 원망하는 글이 됐다. 문단 전체를 다시 읽는다
- 챗봇 인용 같은 근거는 실제 기전으로 바꾼다
- 오타는 고친다 (`곰곰히` → `곰곰이`)
- **절 순서는 시간순이 아니라 축의 순서를 따른다.** 원글 두 편이 1년 간격으로 같은 문제를 다뤘다면 한 절에서 합류시킨다
- 원글 한 편이 층이 다른 문제 두 개를 담고 있으면 두 절로 나눈다 (로컬 자격증명 vs 리버스 프록시)

### URL 처리

사라지는 slug마다 `astro.config.mjs`의 `LEGACY_SLUGS`에 리다이렉트를 넣는다.

**도착지가 사라지면 기존 항목의 값도 갱신해야 한다.** 안 그러면 구 URL이 없는 페이지로 향한다.

```js
// 'tenth-post'가 rn-draggable-button-scrollview로 가고 있었다면
'tenth-post': 'rn-overlapping-layers',                     // 값을 갱신하고
'rn-draggable-button-scrollview': 'rn-overlapping-layers', // 항목을 추가한다
```

묶음마다 원본 삭제와 리다이렉트를 같은 커밋에서 처리한다. 나중에 몰아서 고치면 그사이 구 URL이 죽는다.

### 검증

```bash
npm run build
```

빌드 후 확인한다.

- `LEGACY_SLUGS`의 **값이 실제로 `src/content/blog`에 존재하는지** (도착지 없는 리다이렉트)
- **값이 다시 다른 항목의 키가 아닌지** (리다이렉트 체인)
- 사라진 slug가 `dist/sitemap-0.xml`에 남아 있지 않은지
- 리다이렉트 스텁이 `dist/<slug>/index.html`로 실제 생성됐는지

Disqus는 URL 기준으로 스레드를 묶는다. **댓글이 달린 글을 없애면 스레드가 끊기니 미리 확인한다.**
