## 1. 문체 — 번역투를 걷어낸다

평서체 `~다`. 구어가 조금 섞인 톤. **영어 문장 구조를 그대로 옮긴 흔적이 가장 큰 문제다.**

### 쓰지 말 것 — 문장 틀을 옮긴 것

| 금지 | 이유 | 고침 |
|---|---|---|
| 본문의 `—` (em dash) 삽입구 | 영어 구두점. 한국어는 쉼표·콜론·문장 분리 | `재현됐다 — 글이 등록돼야 한다` → `재현이 됐는데, 글이 등록돼야 했다` |
| 명사형 종결 (`~는 제보.`, `~라는 것.`) | 영어 fragment 직역 | `…없다는 제보.` → `…없다는 제보가 들어왔다.` |
| `~것이다` 남용 | 문장마다 붙으면 번역체 | 서술어로 직접 끝낸다 |
| `주의할 점은 ~는 것이다` | 같은 틀을 글마다 반복하게 된다 | 조건절로 합친다. `~면 동작하지 않으니 ~해야 한다` |
| `X가 하나 있다. Y라는 것이다` | 예고했다가 밝히는 수사가 반복된다 | 뒷문장의 `것이다`를 뺀다 |
| `이유가 여기 있었다` | *herein lay the reason* 직역 | 원인을 **앞으로** 빼서 한국어 순서로 |
| `~는 데 있다` | 위와 같은 뿌리 | `문제는 A라는 데 있다` → `그런데 A다` |
| `~라고는 ~뿐이다` | *the only thing that…* 구조 | `X만 다를 뿐인데 ~` |
| `~보면 금방 안다`, `세어보면 안다` | *count and you'll see*. 결과를 독자에게 미룬다 | `빠진 것을 세어보면 금방 안다` → `정해지지 않는 것이 너무 많다` |
| `앞은 A이고 뒤는 B다` | *the former / the latter* 직역 | 가리키는 대상을 이름으로 부른다. `CPU는 못 바꾸지만 학습 데이터는 바뀐다` |
| `~하게 해주고 ~하게 도와준다` | *helps you do X*. 무생물이 사람을 돕는 구도 | 주어를 사람으로. `덕분에 우리는 ~할 수 있다` |

### 쓰지 말 것 — 단어를 옮긴 것

| 금지 | 원래 영어 | 고침 |
|---|---|---|
| `물론 공짜는 아니다` | *it's not free* | `대신 대가는 있다` |
| `권장되지 않는다` | 불필요한 피동 | `권장하지 않는다` |
| `~쪽이었다`, `~쪽으로` | 뻑뻑하다. 한 문단에 두 번이면 더 나쁘다 | `우회하는 쪽이었다` → `우회하는 방법이었다` |
| 구어 축약 (`거라곤`, `손댄 게 없었고`) | 평서체 글에서 뜬다 | `그대로였다` |
| `필요로 하다` | *need* | `필요하다` |
| `관측 가능한` | *observable* | `겉으로 드러나는` |
| `진행 중이다` | *in progress* | `그 과정을 겪고 있다` |
| `~를 통한` | *through X* | `AI를 통한 코딩` → `AI 코딩` |
| `대부분의 X에서` | *most of* | `X 대부분은` |
| `~로 돌아온다` (비용·결과가) | *comes back as* | `매달 나가는 요금이 늘어난다` |
| `~에 기대다` | *rely on* | `다른 것에 기댄다` → `다른 안전장치를 둔다` |
| `~의 모양이다` | 주술이 안 맞는다 | `학습 데이터의 모양이다` → `학습 데이터를 그대로 따른 결과다` |

### 영어식 서술 순서를 뒤집는다

- **안 바뀐 것 나열 → 바뀐 것 지목** ✕
  `쿼리도 인덱스도 데이터도 그대로인 상태에서 달라진 것이라고는 OFFSET 하나뿐이었다`
- **`X만 다를 뿐인데 ~`** ✓
  `OFFSET 숫자만 다를 뿐인데 이런 현상이 나타났다`

원인은 앞, 결과는 뒤. `A였으니 B다`가 `B인 이유는 A다`보다 낫다.

### 관형절을 습관적으로 만들지 않는다

영어의 관계절·현재분사 수식(*the five traps that braces create*, *six things to watch out for*)을
한국어 관형절로 그대로 옮기는 것이 이 글쓰기에서 가장 자주 나온 실수다.
지적받은 `꿰는` · `놓인` · `부딪히는` · `막히는` · `만드는`이 전부 같은 뿌리에서 나왔다.

**조사로 바꿀 수 있으면 조사가 이긴다.**

| 관형절 | 조사·동사 연결 |
|---|---|
| JSX 중괄호`가 만드는` 다섯 가지 함정 | JSX 중괄호`의` 다섯 가지 함정 |
| Harbor `사용 중에` 마주친 네 가지 문제 | Harbor`를 사용하며` 마주친 네 가지 문제 |

`중괄호가 함정을 만든다`는 관계는 `의` 하나로 전달된다. 동사를 넣으면 중괄호가 능동적인 행위자처럼 되면서
문장이 한 겹 두꺼워진다. 한자어를 명사화한 `사용 중에`도 같은 계열이니 동사(`사용하며`)로 되돌린다.
덤으로 의존명사 `중`의 띄어쓰기 문제도 사라진다.

**관형절이 꼭 필요하면 `-는`이 아니라 `-ㄹ`을 쓴다.**

`실패할 때 보는 다섯 곳` ✕ → `실패할 때 확인할 다섯 가지` ✓

`-는`은 상태를 서술하고 주체도 모호하다. `-ㄹ`은 독자가 할 일을 가리킨다.
실용 글의 제목은 서술이 아니라 지시이므로 `-ㄹ`이 맞다.

**동사는 글의 성격에 맞춰 고른다.**

함정 모음이면 `주의할`, 순서대로 짚어가는 점검 목록이면 `확인할`.
같은 자리에 아무 동사나 넣으면 두 글의 성격이 제목에서 구별되지 않는다.

### 추상어 대신 구체어

`쓰기가 들어오는 쪽 끝에서부터 읽는다` → `새 글은 목록 맨 앞에 꽂히는데, 무한 스크롤은 그 맨 앞에서부터 읽어 내려간다`

독자가 머릿속에 그림을 못 그리면 틀린 문장이다.

### 지위·상태를 공간으로 말하지 않는다

`소스`와 `산출물`, `층`, `경계`처럼 글에서만 쓰는 공간 표현은 그림이 눈앞에 있을 때만 통한다.
본문에서는 무엇이 무엇으로 바뀌는지 매번 이름으로 적는다.

| 쓴 표현 | 고침 |
|---|---|
| 소스에서 산출물로 `내려간다` | 직접 쓰는 코드가 아니라 기계가 뽑아내는 결과물이 `된다` |
| SQL은 더 `멀리 가 있다` | SQL에서는 방법을 사람이 정하지 않는다 |
| 사람이 `한 층 위로` 올라간다 | 사람이 `코드에서 스펙으로` 옮겨간다 |
| 경계가 `어디로 움직이든` | 사람이 `코드를 쓰든 스펙을 쓰든` |

다이어그램에서 위아래로 그린 것을 본문에서도 위아래로 말하면, 그림을 안 보는 독자는 못 따라온다.
같은 이유로 `자리`·`층`·`단계` 같은 말을 한 글에서 세 번 넘게 쓰지 않는다.

### 비유를 쓰지 않는다

문학적 비유는 전부 걷어낸다. 아래는 실제로 지적받아 고친 것들이다.

| 쓴 표현 | 고침 |
|---|---|
| `다섯 가지를 꿰는 한 줄` | `다섯 가지의 공통점` |
| `증상과 원인이 놓인 층` | `층을 먼저 정하는 순서` |
| `무관해 보이지만 놓인 자리가 다르다` | `원인이 다 다른데, 막히는 단계가 순서대로 이어진다` |
| `중괄호의 두 얼굴` | `중괄호의 두 가지 뜻` |
| `같은 문제를 다른 얼굴로 다시 만났다` | `같은 문제를 다시 만났다` |
| `이 순서가 결국 유일한 지도가 된다` | `이 순서를 밟는 것 말고는 방법이 없다` |
| `catch는 나중에 반드시 값을 치른다` | `catch는 나중에 원인을 찾기 어렵게 만든다` |
| `첫 에러는 로그 어딘가에 묻혀 있었다` | `첫 에러는 그보다 앞선 로그에 따로 찍혀 있었다` |
| 소제목 `테두리를 지울 때의 대가` | `초점 표시와 outline: none` |
| `아래 다섯 가지가 같은 이야기로 읽힌다` | `아래 다섯 가지 함정은 모두 이 차이에서 나온다` |

`얼굴` · `뿌리` · `지도` · `꿰다` · `값을 치르다` · `묻혀 있다`가 나오면 멈추고 무슨 일이 일어났는지 그대로 적는다.

비유를 구체어로 바꾸면 정확도가 같이 올라가는 경우가 많다. `로그 어딘가`는 위치를 모른다는 뜻이었는데, 실제로는 앞선 줄에 찍혀 있었다.

**비유를 걷어낼 때 명사구를 쌓아서 대체하지 않는다.** 위 표의 마지막 줄이 실제로 그렇게 실패했다.
`놓인 자리가 다르다`를 고치려고 쓴 `같은 흐름의 서로 다른 단계에서 막힌 것이다`는
비유는 없지만 명사구가 세 겹(`같은 흐름` + `의` + `서로 다른 단계`)이고 `~것이다`까지 붙어 더 나빴다.
비유를 지운 자리에는 **동작하는 동사**를 넣는다 → `막히는 단계가 순서대로 이어진다`.
`2. 문장 길이`의 틀림 B를 같이 본다.

**단, 원글에서 가져온 저자의 말투는 살린다.** 이건 비유가 아니라 사람의 목소리다.

> `편리함에 취해 있던 어느 날` · `바퀴를 다시 발명할 일은 아니라서` · `묘한 배신감이 들었다` · `노가다` · `사람은 가끔 바보가 된다`

걷어내면 남의 문서처럼 읽히고, 검색·심사에서 보는 독창성 신호도 같이 사라진다.

### 마무리 문장에서 멋을 부리지 않는다

지적받은 문장의 대부분이 절이나 글의 **마지막 줄**이었다. 요점을 한 문장으로 봉하려다 비유와 의인화가 들어간다.

| 쓴 표현 | 고침 |
|---|---|
| `여섯 개가 결국 같은 두 가지를 묻고 있다` | `여섯 개는 순서 문제와 타이밍 문제로 나뉜다` |
| `쌓아 올리는 순간부터 순서와 타이밍이 같이 따라온다` | `레이어를 하나 올릴 때마다 둘 다 확인하면 대부분 걸러진다` |

- **무생물을 주어로 세운 동작 동사를 의심한다.** `여섯 개가 묻는다` · `순서가 따라온다` · `catch가 값을 치른다`
  모두 사람이 하는 일을 사물에 붙인 것이다
- **수사 의문문으로 끊지 않는다.** `무엇이 위에 있고, 언제 위로 올라가는가` → 평서문으로 적는다
- 마지막 문장은 **독자가 다음에 할 일**이나 **숫자로 나뉘는 분류**로 끝내는 편이 안전하다

### 연어를 만들어 쓰지 않는다

뜻이 통하는 조합을 새로 만들면 바로 티가 난다. 한국어에서 실제로 함께 쓰는 짝을 쓴다.

| 만든 말 | 실제로 쓰는 말 |
|---|---|
| 컴포넌트를 `겹쳐 올리다` | 컴포넌트를 `쌓아 올리다` |
| 레지스트리를 `세우다` | Harbor를 `띄우다` · `운영하다` |
| 규칙을 `켜다` | 규칙을 `적용하다` |
| 구분을 `잡다` | 구분을 `알다` · 아예 `차이`로 바꾼다 |
| 두 경우가 `갈라지다` | 두 경우가 `갈리다` (`갈라지다`는 금이 가거나 사이가 틀어질 때) |
| 조건을 `걸다` | 조건을 `정하다` · `통과하다` |
| 조건을 `채우다` | 조건을 `갖추다` · `충족하다` |
| 관문을 `세우다` | 통과해야 할 것을 `정해두다` |
| 신뢰를 `만들다` | 신뢰를 `얻다` |
| 관성이 `풀리다` | 관성이 `달라지다` · `깨지다` |
| 가독성 값을 `내다` | 읽기 좋게 `유지하다` |

판단 기준은 뜻이 통하는지가 아니라 **그 분야에서 남들이 그렇게 쓰는지**다.
확신이 없으면 동사를 하나로 줄이고 흔한 쪽을 택한다. `레이어가 겹친다`처럼 원래 있는 짝은 그대로 쓴다.

### 어휘 강도

`사건`(형사 사건 어감), `참사`, `대참사` 같은 과장어를 쓰지 않는다. `문제`, `이슈`로 충분하다.

## 2. 문장 길이 — 두 방향으로 다 틀릴 수 있다

### 틀림 A: 단문 나열

```
비용은 O(offset + limit)이다. 페이지 번호에 선형으로 비례한다. 1페이지가 빠르다.
```

리듬이 끊기고 기계가 쓴 것처럼 읽힌다.

### 틀림 B: 명사구를 쌓아서 늘리기 — **이쪽이 더 나쁘다**

```
쿼리도 인덱스도 데이터도 그대로인 상태에서 달라진 것이라고는 OFFSET 숫자 하나뿐이었다.
```

길어졌지만 자연스러워진 게 아니라 뻑뻑해졌다. 아래 꼬리가 보이면 의심한다.

`~인 상태에서` · `~것이라고는 ~뿐이다` · `~다는 점을 이용한 것이다` · `~하는 구조이기 때문이다` · `~인 양상이었다` · `~하는 것이 조건이었다`

### 맞음: 연결어미로 잇는다

`~는데` · `~어서` · `~니` · `~지만` · `~기 때문에` · `~고`

```
그래서 비용은 O(offset + limit)이 되고, 페이지 번호에 선형으로 비례한다.
1페이지가 빠른 건 인덱스가 잘 잡혀 있어서지만, 5,000페이지가 느린 건 인덱스와 상관이 없다.
```

**기준은 레퍼런스 글의 실측값이다.** 문장 끝으로 잘라 재면 기존 글이 평균 31~42자로 나온다
(`git-hotfix-revert-trap` 31자, `offset-vs-cursor-pagination` 39자, `persona-agent-and-memory` 42자).
초안이 이 아래로 내려가면 단문 나열이고, 크게 웃돌면 명사구를 쌓은 것이다. 다만 억지로 이어서
어색해질 바에는 끊는다. 짧게 남겨도 되는 자리는 문단 끝 강조 한 줄, 인용문, 코드·그림 도입부다.

**평균보다 연속 단문 개수를 본다.** 평균이 범위 안이어도 짧은 문장이 네댓 개씩 이어지면 기계가 쓴 것처럼 읽힌다.

```bash
python3 - <<'EOF'
import re
p = 'src/content/blog/<파일>.mdx'
body = open(p, encoding='utf-8').read().split('---\n', 2)[2]
prose = [l.strip() for l in body.split('\n')
         if l.strip() and not l.strip().startswith(('#','|','-','<','import','*','!','>'))]
sents = []
for l in prose:
    l = re.sub(r'\*\*|`|\[.*?\]\(.*?\)', '', l)
    sents += [x.strip() for x in re.split(r'(?<=[.?])\s+', l) if x.strip()]
lens = sorted(len(x) for x in sents)
print(f'{len(lens)}문장 · 평균 {sum(lens)//len(lens)}자 · 중간값 {lens[len(lens)//2]}자')
run = []
for x in sents:
    run = run + [x] if len(x) < 45 else []
    if len(run) >= 4: print('연속 단문:', ' / '.join(run))
EOF
```

같은 스크립트를 레퍼런스 글에 먼저 돌려 기준선을 잡고 초안과 비교한다. 숫자만 보고 문장을 늘리면 명사구를 쌓게 된다.

## 3. 문법 검사

한 문장 안에서 반드시 확인한다.

- **주술 호응** — `원인이 하나로 모인다` ✕ (원인은 애초에 하나) / `인덱스는 타고 있었다` ✕ (`쿼리는 인덱스를 타고 있었다`) / `정확도를 손해 보다` ✕
- **시제 일치** — 대조절 양쪽을 맞춘다. `달라 보였지만 원인은 하나다` ✕ → `달라 보이지만 사실 원인은 하나다` ✓
- **대조에는 `사실`을** — "달라 보이지만 실은 같다" 구조에서 `사실`이 빠지면 반전이 안 읽힌다
- **같은 어미·단어 반복** — `있었다`가 연달아 두 번, `하필`이 한 문장에 두 번 → 하나를 바꾼다
- **같은 계열 단어를 한 글에서 몇 번 썼는지 센다** — `갈라주다`·`갈리다`·`갈라지다`가 한 글에 네 번이면 눈에 띈다.
  각 단어에 다른 일을 주고 하나는 다른 말로 바꾼다 (규칙을 기기별로 `나누다` / 두 상태가 `갈리다`)
- **주어가 문장 안에 있는지** — `~와 어긋난다`처럼 서술어만 남고 주어가 사라지는 일이 잦다.
  `브라우저가 대신 따라 하는 과정에서 마우스용 CSS와 어긋난다` ✕ (무엇이 어긋나는가) →
  `마우스를 전제로 쓴 CSS는 여기서 엉뚱하게 동작한다` ✓
- **능동과 피동이 뒤집히지 않았는지** — `그 안은 평가해서 값을 내놓아야 하는 코드가 된다` ✕
  (그 안은 평가하는 쪽이 아니라 평가되는 쪽) → `중괄호 안에는 값으로 평가되는 것만 들어갈 수 있다` ✓
- **한 문장에 같은 단어가 세 번** — `마우스는 ... 마우스 동작을 ... 마우스용으로 만든 CSS와` → 문장을 나눈다

### 셈하는 말을 관형절로 받을 때 — 가장 자주 반복한 실수

`가지` · `곳` · `지점` · `단계`는 셈하는 말이라 그 자체가 동작의 주체나 대상이 되기 어렵다.
**`~하는 N가지` 꼴을 제목의 기본값으로 쓰지 않는다.** 실제로 다섯 번 연속 지적받은 자리다.

| 쓴 표현 | 무엇이 어긋났나 | 고침 |
|---|---|---|
| `부딪히는 여섯 가지` | 여섯 가지에 부딪히지 않는다 | `확인할 여섯 가지` |
| `레지스트리가 막히는 네 지점` | 관형절에 주어(`레지스트리가`)가 따로 있어 주어가 둘이 된다 | `Harbor 사용 중에 마주친 네 가지 문제` |
| `레지스트리를 세우고 쓰는 네 단계` | 동사 두 개가 셈하는 말을 함께 수식한다 | `Harbor 기동부터 이미지 pull까지` |
| `A를 만들고, B가 저장하고, C에 그리는 세 지점` | 세 동사의 주체가 다 다르고 `지점`은 그중 무엇도 아니다 | `세 지점을 순서대로 적어둔다. A를 만드는 클라이언트, 저장하는 B, 그리는 C다` |

**주어 자리에도 세우지 않는다.** 관형절만 조심하다가 여기서 세 번 더 걸렸다.

| 쓴 표현 | 왜 틀렸나 | 고침 |
|---|---|---|
| `아래 다섯 가지가 같은 이야기로 읽힌다` | 읽히는 건 `가지`가 아니라 함정이다 | `아래 다섯 가지 함정은 모두 이 차이에서 나온다` |
| `에러 메시지는 다섯 개가 다 달랐는데` | 주어가 둘이고, 다른 것은 `개`가 아니라 증상이다 | `증상은 다 달랐지만 원인은 매번 중괄호였다` |
| `여섯 개는 순서 문제와 타이밍 문제로 나뉜다` | 번호 목록을 가리키므로 `항목`이 정확하다 | `여섯 항목은 순서 문제와 타이밍 문제로 나뉜다` |

`함정` · `증상` · `원인` · `문제` · `항목` 같은 **실제 명사를 주어로 세운다.**
셈하는 말이 주어 자리에 오면 서술어가 그것을 받을 수 있는지 소리내어 확인한다.

고치는 길은 셋이다.

1. **셈하는 말을 목적어로 받는 동사로 바꾼다** — `확인할 여섯 가지`, `세 지점을 끊어서 보기`
2. **실제 명사를 head로 세운다** — `문제`, `함정`, `이유`. `막히는 네 지점` 대신 `만난 네 가지 문제`
3. **범위로 잡는다** — `A부터 B까지`

동사만 구체적인 것으로 바꾸고 구조를 그대로 두면 여전히 어색하다.
`세우고 쓰는` → `띄우고 주고받는`으로 바꿔도 ✕였다. 구조를 먼저 의심한다.

셈하는 말이 제자리에 있으면 문제없다. `여기서 막히는 경우` ✓ · `지점이 막힌다` ✓ · `세 지점의 공통점` ✓

**`곳` · `지점` · `단계`는 실제로 장소·지점·단계일 때만 쓴다.**
서로 다른 다섯 개의 문제는 `다섯 곳`이 아니라 `다섯 가지`다.
본문에서 쓴 비유(`층`)를 제목까지 끌고 가면 이 실수가 난다.

애초에 관형절을 안 만들면 이 절의 문제 절반이 생기지 않는다. `1. 관형절을 습관적으로 만들지 않는다`를 먼저 본다.

### 지시어가 앞을 정확히 가리키는지

표나 목록 뒤에 오는 문단에서 자주 어긋난다.

- **앞에서 부른 이름으로 받는다.** 앞 문장이 `최근 도구들은`인데 뒤에서 `이 단계들은`으로 받으면
  독자는 표를 다시 올려다본다
- **앞 문장이 한 말을 지시어로 되풀이하지 않는다.** 표 뒤 문단은 표를 받아 **공통점**을 말하는
  자리이지, 앞 문장을 다시 쓰는 자리가 아니다
- **조건을 나열할 때 AND와 OR를 확인한다.** `검증기와 테스트를 통과하고 요구사항 매핑이 맞으면`은
  셋을 다 통과해야 하는 것처럼 읽히는데, 표에서는 도구마다 하나씩이었다.
  `조건을 하나 정해두고 그것만 맞으면`으로 고쳐야 표와 맞는다

## 4. 제목과 소제목

### 제목

`제목 — 부제` 형태를 쓴다. 구분자는 `-`가 아니라 `—`다. 부제 없이 제목만 두면 무슨 글인지 안 잡힌다.

- **제목은 검색에 걸리는 말, 부제는 이 글만의 것.** `AI는 개발 언어를 어떻게 바꾸고 있는가`는
  아무 글에나 붙을 수 있어서 그것만으로는 구별이 안 된다. 구체는 부제가 맡는다
- **부제가 본문의 반전을 담으면 제일 좋다.** 위 제목에 `70년 전 어셈블리에 일어난 일`을 붙이면
  질문과 답이 두 줄에 다 들어간다
- **본문 결론과 부딪히는 단어를 쓰지 않는다.** 마지막 절에서 "다시 반복된다"고 쓰는 글에
  `종착지`·`마지막`을 붙이면 제목이 본문을 뒤집는다
- **후보를 낼 때는 성격을 붙여 나열한다.** 역사 축·질문형·연대기처럼 방향이 다른 것으로 뽑아야
  고르는 쪽이 판단할 수 있다. 비슷한 것 네 개는 선택지가 아니다

### 소제목

- **명사로 끝낸다.** `직접 측정해봤다` ✕ → `직접 측정한 결과` ✓
- 의문형·서술형 금지. `실제 서비스는 어떻게 하고 있나` ✕ → `실제 서비스들의 선택` ✓
- `## ▍제목` 형식. `▍` 접두어 유지
- 본문에 소제목 이름을 직접 언급하지 않는다 (`앞 절에서`, `뒤에서 다시 본다` 정도로)

## 5. 도입부

추상적 주장을 던졌으면 **그 문단 안에서 증상을 적는다.** 뒤에서 설명할 거라고 미루면 독자는 무슨 말인지 모른 채 읽는다.

```
✕  하나는 느려지는 문제고, 다른 하나는 틀리는 문제다.
✓  하나는 느려지는 문제고, 다른 하나는 조회 결과 자체가 틀리는 문제다.
   같은 글이 목록에 두 번 나오거나, 분명히 있는 글이 어느 페이지에도 안 나온다.
```

### 글에서만 쓰는 용어는 첫 등장에서 정의한다

축을 세우면 그 축의 이름(`소스`·`산출물`·`스펙`)을 글 내내 쓰게 되는데, 정의 없이 도입부에 던지면
독자는 무슨 말인지 모르는 채로 읽는다. 첫 등장 자리에서 인용 한 줄로 묶는다.

> 여기서 스펙(Spec)은 자연어로 된 기능 정의 파일을 뜻하고, 생성기는 스펙을 읽고 코드를 작성한다.

정의에 쓰는 말은 독자가 이미 아는 것이어야 한다. `소스 자리에 놓이는 파일`처럼 아직 설명 안 한 말로
다른 말을 설명하면 정의가 하나 더 필요해진다.

## 6. 코드블록 · NoteBlock · 다이어그램

| 내용 | 형식 |
|---|---|
| 실제 실행하는 코드, SQL, 설정 | ` ```sql ` / ` ```js ` 등 |
| 실행 결과 원문 (EXPLAIN 출력, 로그) | ` ```text ` |
| 용어 정의, 한 줄 보충 설명 | 인용 (`>`) |
| 주석·화살표를 붙인 설명용 의사 출력 | `NoteBlock` (`label` + `text`) |
| 비교, 타임라인, 정답이 있는 선택지, 구조 | **SVG 다이어그램 컴포넌트** |

### 설명 하나에 컴포넌트를 만들지 않는다

한 줄이면 끝나는 설명에 전용 컴포넌트를 만들면 글보다 상자가 커진다. 순서대로 내려간다.

1. 본문 한 문장으로 되는가
2. 안 되면 인용 (`>`)
3. 그래도 안 되면 표
4. 새 컴포넌트는 같은 형식을 여러 글에서 반복해 쓸 때만

"설명 UI를 넣어달라"는 요청이 곧 새 컴포넌트를 만들라는 뜻은 아니다. 인용부터 대본다.

**`NoteBlock`에 한국어 산문을 넣지 않는다.** `white-space: pre`라 줄바꿈이 안 돼서 가로로 넘친다.
`NoteBlock`은 ASCII 라벨로 열을 맞춘 의사 출력 전용이고, 산문 설명은 인용으로 간다.

### 반드시 다이어그램으로 갈 것

1. **정렬에 의존하는 ASCII 블록** — prettier가 공백을 뭉개서 반복적으로 깨진다. 좌표 기반 SVG는 안 깨진다.
2. **정답/오답이 있는 비교** — `X`/`O` 글자 하나로는 안 보인다. 정답 카드에 테두리 두께, 배경, `이게 정답` 라벨까지 준다.
3. **타임라인, 전후 비교** — 같은 값이 같은 열에 오도록 배치하면 차이가 한눈에 보인다.

### 코드블록 안에서 한글로 열을 맞추지 않는다

본문 코드블록은 JetBrains Mono에 한글 폴백이 붙는 구조라 **한글 글자폭이 라틴 문자의 정확히 2배가 아니다.**
소스에서 아무리 정확히 패딩해도 브라우저에서 어긋난다. 터미널에서 맞아 보이는 것에 속지 말 것.

```text
키 없이 c1, c2와 p1만으로 복원한 p2: 01098765432   ✕ 라벨에 한글이 섞여 콜론이 안 맞는다
실제 p2                          : 01098765432

p2 recovered = 01098765432                        ✓ 정렬 구간이 전부 ASCII
p2 actual    = 01098765432
```

고치는 길은 둘이다.

1. **라벨을 ASCII로 바꾼다.** 실행 결과라면 스크립트의 `console.log` 라벨부터 영문으로 바꿔 다시 뽑는다.
   한글은 정렬이 끝난 뒤(줄 끝 주석 등)에만 둔다
2. **표로 옮긴다.** 애초에 열이 셋 이상이면 `text` 블록이 아니라 마크다운 표가 맞다.
   측정 결과를 그대로 붙이고 싶은 유혹이 생기는 자리인데, 헤더에 한글이 들어가는 순간 깨진다

SQL·코드 주석처럼 **정렬 지점이 전부 ASCII이고 한글이 그 뒤에만 오면** 안전하다.

```bash
# 코드블록에서 한글 + 다중 공백 정렬을 쓴 줄 찾기 (줄 끝 한글 주석은 오탐)
python3 - <<'EOF'
import re
s = open('src/content/blog/<파일>.mdx', encoding='utf-8').read()
for m in re.finditer(r'```(\w*)\n(.*?)```', s, re.S):
    for l in m.group(2).split('\n'):
        if re.search(r'[가-힣]', l) and re.search(r'\S {2,}\S', l):
            print(f'[{m.group(1)}] {l}')
EOF
```

### 표로 두어야 할 것

**대응 관계는 표다.** 증상↔원인, 단계↔확인할 것처럼 두 열이 짝을 이루면 표가 더 정확하다.
그림으로 그리면 평행선 N개가 되어 표보다 못하다.

**순서·교차·단계 진행은 그림이다.** 코드 순서가 z축을 뒤집는 것, 앞 단계가 풀려야 다음 문제가 보이는 것처럼
관계 자체에 방향이 있을 때만 SVG로 간다.

그림이 하나도 없는 글이 있어도 된다. 억지로 만든 그림은 없는 것보다 나쁘다.

### 중복 금지

그림을 그렸으면 **같은 내용의 텍스트 블록은 지운다.** 숫자·구성·결론이 같으면 중복이다.
그림을 소개하던 문장이 붕 뜨지 않게 앞뒤 문장도 같이 손본다.

### 커버 이미지

`![alt](/img/<slug>-cover.webp)`를 import 다음, 첫 문단 앞에 둔다.

- 파일명은 **글 slug + `-cover`**, 확장자는 `webp`
- PNG를 받았으면 변환한다. 2MB짜리가 100KB 안쪽으로 줄어든다

```bash
cwebp -q 82 <원본.png> -o public/img/<slug>-cover.webp
```

- alt에는 그림에 무엇이 있는지 적는다. 제목을 그대로 옮기지 않는다
- 커버가 없는 글도 있다. 억지로 만들지 않는다

### 대칭 케이스는 형식도 대칭으로

삽입/삭제, 성공/실패처럼 짝을 이루는 케이스는 한쪽만 그림, 한쪽만 텍스트로 두지 않는다.
단, 본문이 "방향만 반대일 뿐 똑같다"고 명시적으로 축소하는 경우는 예외로 둘 수 있다.

## 11. 작업 절차

### 편집기가 켜져 있을 때

dev 서버나 편집기에 파일을 열어둔 채로 고치면, 편집기가 이전 버퍼를 저장하면서 방금 한 수정이
통째로 사라진다. 실제로 컴포넌트 파일을 지운 뒤 본문 import만 되살아나 모듈을 못 찾는 오류가 났다.
포매터가 같이 돌면 따옴표까지 `'`에서 `"`로 바뀌므로 앵커 문자열도 안 맞게 된다.

- **컴포넌트 파일을 지우기 전에 본문 참조를 먼저 지우고 빌드로 확인한다**
- 고친 뒤에는 `grep -rn "<이름>" src/`로 지운 이름이 정말 없는지 다시 본다
- 앵커가 안 맞으면 파일이 되돌아갔는지부터 의심한다. 현재 내용을 다시 읽고 앵커를 새로 잡는다
- 사용자가 직접 고친 문장이 섞여 있을 수 있으니, 되살아난 파일을 통째로 덮어쓰지 않는다

### 편집

MDX 본문을 고칠 때는 **python 치환 + assertion**을 쓴다. sed는 한국어·백틱·특수문자에서 위험하다.

```python
def rep(a, b):
    global s
    assert s.count(a) == 1, a[:40]   # 앵커가 유일한지 반드시 검증
    s = s.replace(a, b)
```

글 전체를 다시 쓸 때는 코드블록이 그대로인지 검증한다.

```python
import re
blocks = lambda t: re.findall(r"```[a-z]*\n.*?```", t, re.S)
assert blocks(old) == blocks(new), "code blocks changed"
```

### 검증

```bash
npm run build          # MDX 파싱 + 다이어그램 렌더 확인
grep -n "^## ▍" <파일>  # 소제목 명사형 확인
grep -n "—" <파일>      # 본문 em dash 잔여 (제목·코드주석·링크는 예외)
```

**초안을 넘기기 전에 번역투를 한 번 훑는다.** §1에 규칙이 있어도 쓰면서는 안 걸리고,
넘긴 뒤에 지적받는다. 아래는 실제로 반복해서 걸린 것들이다.

```bash
# 피동·진행형 직역
grep -nE "입장에서|고 있었다|되어졌|만들어[진졌]|놓여 ?있|이루어[진졌]|여겨[진졌]|보여진" <파일>
# 영어 동사·형용사 직역
grep -nE "필요로 하|관측 가능|방향으로 가|의 경우에는|진행 중|를 통한|도와준다|해준다" <파일>
# 영어 문장 틀 직역
grep -nE "보면 금방 안다|세어보면|앞은 .{1,20}뒤는|로 돌아온다|의 모양이다" <파일>
# most of 직역
grep -nE "대부분의 [가-힣]+(에서|은|는|이|가)" <파일>
# 무생물 주어 + 관형절
grep -nE "[가-힣]+(하는|되는|드는) (일|것|점)(은|이) " <파일>
# 짧은 부정 (긴 부정으로)
grep -nE "안 [가-힣]" <파일>
# and 나열을 조사로 이어붙인 것 (쉼표로)
grep -nE "[가-힣]와 [가-힣]+와 [가-힣]+와" <파일>
```

시간 표현이 겹치는 것도 자주 나온다. `만들기 시작했을 때, 당시 프로그래머들은`에서 `때`와 `당시`가
같은 일을 한다. `~했을 때` 뒤에 `당시`·`그때`·`그 무렵`이 오면 하나를 지운다.

grep으로 안 잡히는 것은 눈으로 본다. 문장마다 **주어가 사람인지 사물인지**를 보고,
사물이 주어인데 동작 동사가 붙어 있으면 고친다. 만든 연어(`신뢰를 만들다`·`가독성 값을 내다`)도
같은 자리에서 걸린다.

### 리뷰 요청을 받았을 때

한 문장씩 지적받는 상황이면 그 문장만 고친다. 주변까지 손대면 무엇이 바뀌었는지 추적이 안 된다.
다만 **같은 패턴이 다른 곳에도 있으면 함께 찾아서 보고한다.** 고칠지는 물어본다.

## 최종 체크리스트

**문체**

- [ ] §11의 번역투 grep을 전부 돌렸다
- [ ] 본문에 `—`가 없고, 명사형으로 끊은 문장이 없다
- [ ] 문학적 비유와 공간 비유가 없다 (`얼굴`·`뿌리`·`값을 치르다` / `층`·`경계`·`내려간다`)
- [ ] 만들어 쓴 연어가 없다 (`조건을 걸다`·`신뢰를 만들다`·`관문을 세우다`)
- [ ] 무생물을 주어로 세우고 사람이 하는 동작 동사를 붙인 문장이 없다
- [ ] 같은 계열 단어를 한 글에서 세 번 넘게 쓰지 않았다
- [ ] 원글에서 가져온 1인칭 말투는 지우지 않고 남겼다

**문장**

- [ ] 모든 문장에 주어와 목적어가 있고, 능동·피동이 뒤집히지 않았다
- [ ] 셈하는 말(`가지`·`곳`·`지점`)을 주어로 세우지 않았고, 실제로 그것일 때만 썼다
- [ ] 대조절의 시제가 일치한다
- [ ] 문장 평균이 31~42자이고, 연속 단문이 네 개 이상 이어지지 않는다

**구성**

- [ ] 제목에 부제가 있고, 부제가 이 글만의 내용을 담는다
- [ ] 제목·소제목이 명사로 끝나고, 관형절을 조사로 줄일 수 없는지 확인했다
- [ ] 도입부의 추상적 주장에 증상이 붙어 있다
- [ ] 글에서만 쓰는 용어를 첫 등장 자리에서 정의했고, 정의에 쓴 말도 독자가 아는 것이다
- [ ] 앞 절에서 깔아둔 대비를 뒤에서 회수할 때 같은 단어를 쓴다
- [ ] 표·목록 뒤 문단의 지시어가 앞에서 부른 이름과 같고, 앞 문장을 되풀이하지 않는다
- [ ] 같은 대상을 여러 이름으로 부르지 않았다 (`모델`·`LLM`·`생성기`)

**형식**

- [ ] 대응 관계는 표로, 순서·교차는 그림으로 갔다
- [ ] 한 줄 설명에 컴포넌트를 새로 만들지 않았다 (본문 → 인용 → 표 → 컴포넌트 순)
- [ ] 그림과 텍스트 블록이 중복되지 않는다
- [ ] 정렬에 의존하는 ASCII 블록이 없고, 코드블록에서 한글로 열을 맞추지 않았다
- [ ] `**…(Term)**조사` 형태가 없다 (닫는 `**` 앞이 괄호면 강조가 안 닫힌다)
- [ ] import만 하고 렌더링하지 않는 컴포넌트가 없다
- [ ] 다이어그램을 건드렸다면 `references/diagrams.md`의 규격을 전부 확인했다
- [ ] 커버 이미지가 `webp`이고 파일명이 `<slug>-cover`이며 alt가 그림 내용을 적는다

**사실과 절차**

- [ ] 수치를 실제로 측정했고 방법을 밝혔다
- [ ] 연도·이름 같은 사실을 확인했고, 추정을 단정형으로 쓰지 않았다
- [ ] 출처가 본문이 아니라 참고 목록에 있다
- [ ] (합치기) `references/merging-posts.md`의 리다이렉트 검증을 통과했다
- [ ] `npm run build` 통과
