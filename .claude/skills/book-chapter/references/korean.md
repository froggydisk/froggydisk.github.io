# 어색한 한국어 — 실제 교정 목록

전부 froggydisk.github.io의 책 원고에서 **한 번씩 지적받고 고친 것들**이다.
뜻이 통하는지가 아니라 **한국어에서 실제로 그렇게 쓰는지**가 기준이다.
확신이 없으면 동사를 하나로 줄이고 흔한 쪽을 택한다.

**✕ 열의 백틱은 그대로 검사가 된다.** `scripts/check-rules.py`가 첫 열의 백틱 문구를 뽑아
원고에서 찾으므로, 여기 규칙을 적으면 검사도 같이 는다. 그래서 **백틱은 그 문구만 보고
틀렸다고 말할 수 있을 때만 두른다.** 앞뒤가 있어야 판정되는 말은 백틱 밖에 적는다 —
`갈린다`는 그 자체로는 멀쩡하고 `네 갈래로 갈린다`가 틀린 것이라, 백틱을 뒤쪽에 두른다.

## 1. 영어 문장 구조 직역

| 쓴 말 | 원래 영어 | 고침 |
|---|---|---|
| `~를 가진다` · `5가지의 동작을 가지는데` | *have* | `~로 나뉜다` · `~는 다섯 가지다` |
| `~에 위치하다` | *be located* | `~에 들어 있다` |
| `CPU라는 이름으로 다시 묶인다` | *under the name of* | `그 칩을 CPU라고 부른다` |
| `입력 장치를 통해 ~ 이는 컴퓨터를 통해 정보라는 형태로 도출된다` | *through / this / is derived as* | `입력장치로 들어온 원시자료는 처리를 거쳐 정보가 되어 나온다` |
| `다만 이 다섯은 하드웨어만 놓고 센 것이다` | *however / it is that* | 서술로 끝낸다 |
| `세 요소를 잇는 것은 내부 버스이고` | *what connects X is Y* | `ALU와 레지스터, 제어 유닛은 내부 버스로 연결된다` |
| `데이터만 양방향인 것은 ~해서이고` | *the reason X is ...* | `CPU는 읽기도 쓰기도 하니 데이터 버스만 양방향이고` |
| `~이유는 ~라서 ~때문이다` | 이중 이유절 | 하나만 남긴다 |
| `~달라지는 것, ~달라지는 것, ~달라지는 것이다` | 명사절 나열 | `장치 안, 시스템 지표, 주고받는 방식이다` |
| `계산하는 위치가 바뀌는 것이다` | *it is that ...* | `계산하는 위치가 바뀐다` |
| `~인 만큼` · `~이며` | 문어 접속 | `~인 만큼` → `~는 만큼`, `~이며` → `~인데` |

`~것이다`는 문장마다 붙으면 번역체다. 서술어로 직접 끝낸다.

## 2. 수사 + 명사 어순

한국어는 영어처럼 수사를 명사 앞에 그냥 붙이지 않는다. **분류사가 필요하다.**

| ✕ | ✓ |
|---|---|
| `다섯 장치` | `장치 다섯 가지` · `다섯 가지 장치` |
| `세 요소` | `셋은` · 이름을 그대로 나열 |

**층 · 개 · 가지는 그 자체가 분류사**라서 `다섯 층` · `다섯 개` · `네 가지`는 맞다.

**`갈래`는 뺐다 (2026-09-21 저자 지시).** 저자가 `## 환각의 갈래`를 두고 **"갈래라는 말은 잘 안 쓰는
말이라서 어색해"**라고 했다. 분류사로 성립하기는 하지만 쓰는 사람이 적다 — §4의 잣대(뜻이 통하는지가
아니라 실제로 그렇게 쓰는지)가 여기에도 걸린다. 세는 자리는 `가지`, 이름 자리는 `종류`로 쓴다.
책에서 다섯 곳과 그림 주석 두 곳을 고쳤다. **이 문서가 ✓로 적어 둔 말이 저자에게 걸린 두 번째 경우다**
(첫째는 `동작했다`, §5).

`가지`는 의존명사라 반드시 띄어 쓴다. `다섯가지` ✕ → `다섯 가지` ✓

### 수사 뒤에 `의`를 붙이지 않는다 (2026-09-19)

`네 번의 실패` · `두 개의 독립 조회` · `질문 네 개의 관찰`은 *four failures of* 꼴이다.
한국어는 수량을 서술로 푼다.

| ✕ | ✓ |
|---|---|
| `네 번의 실패와 그 뒤에 붙인 단계` | `무엇이 깨졌고 그 자리에 무엇을 붙여야 하는지` |
| `두 개의 독립 조회로 나누고` | `독립 조회 둘로 나누고` |
| `질문 네 개의 관찰은 일반화할 수 없다` | `질문 네 개를 보고 전체 업무를 말할 수 없다` |
| `re:[0-9한두세네다섯여섯일곱] ?번의 [가-힣]` | (꼴 규칙 — 사건 명사 앞의 수사+의를 잡는다) |

**`한 번의 처리` · `384개의 숫자`처럼 굳은 짝은 둔다.** 가르는 것은 뒤에 오는 말이
사건이냐 사물이냐다 — 사건(`실패` · `관찰` · `조회`)에 `의`를 붙이면 영어 직역이 된다.

### `정리하면 ~이 된다`는 편집자의 말이다

소설은 "정리하면 N줄이 된다"고 말하지 않는다. **사람이 적는 동작**으로 쓴다.
이 꼴은 §1의 로드맵 금지와 같은 뿌리다 — 저자가 독자에게 글의 구조를 설명하는 자리다.

```
✕  네 번의 실패와 그 뒤에 붙인 단계를 정리하면 일곱 줄이 된다.
✓  무엇이 깨졌고 그 자리에 무엇을 붙여야 하는지는 일곱 줄로 적어 뒀다.
```

`요약하면` · `간추리면` · `~로 정리한다`도 같다. 다만 frontmatter의 `description`은
글이 아니라 색인이라 `~를 그림으로 정리한다`가 정상이다.

| ✕ | ✓ |
|---|---|
| `re:^[^-|].{0,50}(정리하면|요약하면|간추리면)[^.]{0,20}이 된다` | 사람이 적는 동작으로 |

## 3. 만들어 쓴 연어

**뜻이 통해도 그 분야에서 안 쓰면 틀린 것이다.**

| 만든 말 | 실제로 쓰는 말 |
|---|---|
| 펌웨어가 둘을 `잇는다` · 프로토콜로 `잇는다` | `연결한다` |
| 신호가 선을 `탄다` · 선으로 `흐른다` | (문장 자체를 지웠다. 뒤 문장이 이미 경로를 설명했다) |
| 버스가 밖으로 나가 `닿는다` | 버스 세 개가 `나간다` |
| 펌웨어가 하드웨어에 `붙어서 나온다` | 하드웨어에 `담겨 나온다` |
| 선 없이 `붙는` 입력 | 선 없이 `연결되는` 입력 |
| TPU와 NPU까지 `붙는다` | `쓰인다` |
| VVLSI를 `붙이기도 한다` | `VVLSI라고 부르기도 한다` |
| `선으로 붙던 자리에 들어온다` | 유선에서 무선으로 `바뀌고 있다` |
| F/W를 따로 `세운다` | 따로 `둔다` |
| 제어장치가 흐름에 `끼지 않고` | 자료를 `직접 처리하지 않고` |
| 여러 전압을 `구동하고 제어한다` | 여러 전압을 `함께 다룬다` |
| 사실이 흐려지고 점이 가려진다 | (문장을 지웠다) |
| 층이 `네 갈래로 갈린다` | 네 갈래로 `나뉜다` |
| 각 층을 `차지한다` | `~로 나뉜다` |
| 값을 `여기 두고` 나머지는 밖에 둔다 | `레지스터에 들어가고 나머지는 기억장치에 남는다` |

**부품이 기판에 실장된다는 뜻의 `붙는다`는 맞다** — `주변장치가 한 보드에 같이 붙는다` ✓
`구분이 흐려진다`도 실제로 쓰는 짝이다 — `주기억장치와 보조기억장치의 구분이 흐려진다` ✓

**아래 셋은 말 자체가 아니라 무엇이 그러느냐로 갈린다.** 2026-09-19에 검사를 돌려 보니
셋 다 정상 용례에서 더 많이 걸려서 백틱 범위를 좁혔다.

| 말 | ✕ (사물이 부분으로) | ✓ (판단·구분이) |
|---|---|---|
| 갈리다 | `네 갈래로 갈린다` → `나뉜다` | `해석이 갈린다` · `두 모델이 갈린다` |
| 가려지다 | `점이 가려진다` (앞 문장과 겹쳐 지웠다) | `치명적인 실패가 가려진다` |
| 밖에 두다 | `여기 두고 나머지는 밖에 둔다` (여기·밖이 어디인지 없다) | `느린 임베딩을 트랜잭션 밖에 둔다` |

### 깨진다 · 갈린다 · 열다 (2026-09-20 저자 지시)

저자가 셋을 한꺼번에 짚었다. **"전부 웬만하면 번역투야."** 셋 다 국어에 있는 말이지만
쓰는 자리가 좁다. **무엇이 그렇게 되는지**를 보고 가른다.

| ✕ | ✓ | 원문 |
|---|---|---|
| `그 조건을 깨는 상황` | `그 조건을 어기는 상황` | break a rule |
| `질문이 R2를 깨고 … R7이 깨진다` | `봇이 R2를 어기고 … R7을 어긴다` | 규칙은 어기는 것이지 깨는 것이 아니다 |
| `요구사항을 하나씩 깨뜨려 보려고` | `요구사항을 하나씩 어겨 보려고` | |
| `통제가 깨지므로` | `통제가 뚫리므로` | |
| `임베딩 전에 이미 뜻이 깨진다` | `… 뜻이 흐트러진다` | |
| `문맥 구성이 깨졌을 수도` | `문맥 구성이 잘못됐을 수도` | |
| `그다음 처리가 반대로 갈린다` | `… 반대로 달라진다` | diverge |
| `시스템 사이에서 해석이 갈린다` | `시스템마다 해석이 달라진다` | |
| `결과가 갈리면` | `결과가 서로 다르면` | |
| `증거가 있는 기능부터 연다` | `… 기능부터 내놓는다` | open a service |
| `나머지 직원에게는 … 다시 열기로 했다` | `나머지 직원은 … 다시 쓰게 하기로 했다` | §7이 이미 `직원들에게 열어 준다`를 막고 있었는데 다시 썼다 |

**고쳐 놓은 `어기다`도 틀렸다 (같은 날 저자가 다시 짚었다).** `깨다`를 버리면서 `어기다`를
골랐는데, **어기는 것은 사람이 약속·법을 어길 때 쓰는 말이다.** 봇에 붙이면 봇이 규칙에
동의해 놓고 배신한 것처럼 들린다.

| ✕ | ✓ |
|---|---|
| `그 조건을 어기는 상황을 만들어` | `봇이 그 조건을 놓치는 상황을 만들어` |
| `질문이 들어오면 봇이 R2를 어기고` | `들어온 질문은 R2에서 걸리고` |
| `요구사항을 하나씩 어겨 보려고` | `요구사항을 하나씩 건드려 보려고` |

**`걸리다`가 이 책의 말이다** — 1장이 이미 `첫 주에 네 군데가 걸렸다`로 쓰고 있었다.
낱말을 바꿀 때는 **그 책이 이미 쓰는 말** 중에서 고른다.

### 몫 (2026-09-20)

**몫은 나누어 받는 것이지 하는 것이 아니다.** `~가 하는 몫`·`~가 만들 몫`은 쓰지 않는다.

| ✕ | ✓ |
|---|---|
| `모델이 하는 몫과 자기들이 만들 몫부터 나눠` | `모델이 할 수 있는 일과 그 앞뒤에서 직접 만들어야 할 일부터 나눠` |

`운영자의 몫이 된다` · `모델이 판단할 몫이 아니다`는 그대로 둔다 — **`누구의 몫이다`꼴은 정상이다.**

고친 판이 `모델이 할 수 있는 일`을 쓰는 데는 이유가 하나 더 있다. 그 장의 제목이
「모델이 할 수 있는 일과 선택 기준」이고 결어도 같은 말로 닫는다. **제목 · 도입 · 결어가
같은 말로 묶인다**(SKILL.md §1 「장을 닫는 법」).

**셋 다 그대로 두는 자리가 있다.** `글자가 깨진다`(인코딩) · `통신이 깨진다` ·
`로그를 열어 봤다` · `폴더를 열어` · `짧은 쓰기 트랜잭션을 연다` · `헷갈리다`.
`check-book.py`의 「번역투 동사」는 목적어를 붙여 이 자리들을 피해 간다.

## 4. 뜻이 안 통하는 단어를 고르지 않는다

**독자가 “이 말이 무슨 뜻이냐”고 물으면 그 단어는 실패한 것이다.** 아래는 전부 그렇게 지적받고 바꾼 것들이다.
한자어를 쓰면 격식 있어 보인다는 감각을 경계한다. 이 책은 외래어를 이미 쓰고 있으므로
(프롬프트·토큰·청크·스키마·캐시) 굳이 한자어로 옮겨 뜻을 흐릴 이유가 없다.

| 쓴 말 | 무엇이 문제였나 | 고침 |
|---|---|---|
| `도우미` | 청소 도우미의 그 말. 소프트웨어에 붙으면 낡고 뜻이 좁다 | `봇` |
| `시연` | 보여 주는 *행위*라서 `시연을 만든다`가 성립하지 않는다. 예제 파일 이름도 `*_demo.py`다 | `데모` |
| `계수` | 計數인지 係數인지 읽는 쪽이 모른다. 하는 일은 토큰을 세는 것뿐이다 | `토큰 세기` · `센다` · `토큰 수` |
| `대역` | 代役. test double의 번역어지만 `대역 계획기`만 보면 주파수 대역으로 읽힌다 | `가짜` |
| `역압` | 유체역학 직역. 소프트웨어에서 이렇게 쓰는 사람이 없다 | `백프레셔` |
| `원가` | 회계 용어. 여기서 재는 것은 그냥 비용이다 | `비용` |

**바꾼 뒤 조사를 반드시 다시 본다.** 받침이 바뀌면 조사가 전부 틀린다 —
`시연은/을/과` → `데모는/를/와`, `도우미가/를` → `봇이/을`. 치환 직후 `grep -o "<새말>[가은는을를와과]"`로 훑는다.

**그림 안의 라벨도 같이 고친다.** 본문만 고치고 `src/components/diagrams/*.astro`를 빼먹기 쉽다.
라벨이 길어지면 상자를 넘치므로 `scripts/render-diagrams.py`로 눈으로 확인한다.

### 못하다와 `-ㄹ 수 없다` (2026-09-20 저자 지시)

저자가 절 제목 `답하지 못할 때`를 `답할 수 없을 때`로 고쳤다. 둘은 바꿔 쓸 수 있는 말이 아니다.

| 무엇이 막았나 | 쓰는 말 | 예 |
|---|---|---|
| 주체의 능력·마음이 모자랐다 | `못하다` | `개발팀은 선뜻 답하지 못했다` · `모델이 올라오지 못한다` |
| 조건·설계상 애초에 안 되는 자리다 | `-ㄹ 수 없다` | `답할 수 없을 때` · `근거가 없으면 답할 수 없다` |

**서비스가 설계로 정해 둔 상태에 `못하다`를 쓰면 봇이 모자란 것처럼 들린다.**
`답할 수 없을 때`는 서비스가 그렇게 하기로 정한 자리다. 책 전체의 나머지 `~지 못하다`
스물세 곳은 전부 첫째 줄이라 그대로 뒀다.

## 5. 사실만 적으면 번역서가 된다

**가장 늦게 깨달은 것이라 맨 앞에 둔다.** 이 문서의 `사실만 적는다` · `얼버무리지 않는다` ·
`유보문을 줄인다`를 지키다 보면 문장에서 화자가 사라진다. 그러면 정확하지만 **번역서**가 된다.
한국어 수필은 같은 사실에 **화자의 평가를 부사 하나로** 얹는다.

| 사실만 (번역서) | 화자가 있는 (수필) |
|---|---|
| `나흘 사이에 일어난 일이다` | **고작** 나흘 사이에 일어난 일이다 |
| `직원들이 쓰기 시작하자` | **막상** 직원들이 쓰기 시작하자 |
| `총무팀이 개발팀을 찾아갔다` | **결국** 총무팀이 개발팀을 찾아갔다 |
| `이 프로그램이 답했다` | **예상외로** 잘 동작했다 |
| `이달 들어 열한 번째였다` | 이달 들어 **벌써** 열한 번째였다 |

쓸 수 있는 말 — `고작 · 겨우 · 벌써 · 결국 · 막상 · 정작 · 하필 · 그제야 · 곧잘 · 예상외로 · 이미 · 아직`.

**남발하지 않는다.** 장면이 바뀌는 자리와 **사건의 크기를 독자가 가늠해야 하는 자리**에 하나씩이다.
`나흘`이 긴지 짧은지 독자는 모른다. 그걸 알려 주는 것이 `고작`이고, 이건 문체가 아니라 **정보**다.

**낱말이 아니라 원리를 따른다**와 **저자가 고친 문장은 되돌리지 않는다**는
`SKILL.md` §1로 옮겼다. 여기 겹쳐 적지 않는다. 기록만 남긴다 — `동작했다`는
2026-09-17에 ✕, 2026-09-18에 ✓로 박혔다가, 2026-09-19에 저자가 `예상외로 잘 동작했다`로
되돌렸다. 세 번 뒤집혀서 `check-prose.py`의 검사에서 뺐다.

## 6. 문장을 이어 쓴다 — 단문 나열

**`~다.`로만 끝나는 문장이 한 문단에 네 개 이상 이어지면 번역 초고처럼 읽힌다.**
사실이 다 맞아도 독자는 “전개가 잘려 있다”고 느낀다. 이 책에서 가장 여러 번 지적받은 항목이다.

```
✕  개발팀의 한 사람이 그날 오후에 시험 삼아 코드를 짠다. 교육비 규정 문서를 통째로 읽어
   질문 뒤에 붙이고, 언어 모델에 넘기고, 돌아온 문장을 화면에 띄운다. 코드는 한 화면에 들어간다.
   답이 맞다. 질문을 바꿔 가며 몇 번 더 물어도 맞다. 회의에서 이것을 보여 주자 다음 분기부터
   전 직원이 쓰기로 정해진다. 그리고 열어 준 첫 주에 네 가지가 깨진다.

✓  개발팀은 그날 오후에 바로 작업에 착수했다. 교육비 규정과 사내 안내문 몇 장을 한 폴더에
   모아 두고, 질문이 들어오면 그 문서를 통째로 읽어 질문 뒤에 붙이고, 그대로 언어 모델에
   넘기고, 돌아온 문장을 화면에 띄우는 것이 전부였다.

   만들어 놓고 총무팀 담당자를 불러 직접 물어보게 했는데, 예상외로 잘 동작했다. 담당자가
   “교육비 신청은 어디서 하나요?”라고 묻자 지원 포털에서 신청하라는 답이 돌아왔고, 팀장
   승인이 먼저인지 결제가 먼저인지 묻자 승인을 먼저 받으라고 했다.
```

위 ✓는 2026-09-19판이다. 그 사이에 같은 대목을 세 번 고쳤으니 **이 문서의 예시를 그대로
베끼지 말고 원고의 현재 문장을 본다.**

**쓸 수 있는 이음말** — 접속사 `그런데 · 그래서 · 결국 · 다만 · 반면 · 대신 · 그리고`,
연결어미 `-는데 · -어서 · -니까 · -지만 · -면서 · -다가 · -자 · -므로 · -라서 · -기 때문이다`.

**장면이 꺾이는 문장에는 접속사를 붙인다.** `하지만` · `그런데` · `결국`이 없으면
사건이 그냥 나열된 것처럼 읽힌다. 특히 **문단 첫 문장**에서 자주 빠뜨린다.

**다만 문단머리 접속사는 필요조건이지 충분조건이 아니다.** 2026-09-19에 지적받은 도입부는
세 문단이 각각 `그런데` · `하지만`으로 시작하고 있었는데도 끊겨 읽혔다. 접속사를 문단머리에
달아 놓고 **문단 안은 안 이었기** 때문이다. 이음을 문장 안으로 내리면 접속사가 필요 없어진다.

```
✕  그런데 이 프로그램이 곧잘 답했다. 질문을 이리저리 바꿔 물어도 …
✓  만들어 놓고 총무팀 담당자를 불러 직접 물어보게 했는데, 예상외로 잘 동작했다. …
        └ 이음이 문단머리가 아니라 문장 안(-는데)에 있다
```

**문단에도 길이를 잰다 (2026-09-21).** 『AI 엔지니어링』의 산문 문단 435개는 평균 211자인데
그중 둘이 799자(13문장)와 622자(12문장)였다. 읽는 쪽은 그 자리에서 벽을 만난다.
**평균의 세 배를 넘으면 주제가 바뀌는 이음매를 찾아 끊는다.** 이음매는 대개 개념에서 구현으로
넘어가는 자리, 또는 무엇을 하는지에서 무엇을 못 하는지로 넘어가는 자리에 있다.
**새 문장을 쓰지 말고 끊기만 한다.** 끊을 자리가 안 보이면 두 가지를 말하는 문단이 아니라
한 가지를 길게 말하는 문단이니 그대로 둔다.

**이 규칙은 장면 문단에만 건다.** 규칙을 늘어놓는 설명 문단은 끊겨 있는 것이 맞다 —
`~하지 않는다. ~를 확인한다.`는 별개 규칙이라 §9가 오히려 잇지 말라고 한다.
2026-09-19에 `check-prose.py`를 돌려 보니 걸린 13문단 중 12개가 규칙 나열이라 과거형
문단만 보게 좁혔다.

**단문을 남겨 두는 자리는 따로 있다.** 장면의 전환점과 문단의 마지막 한 방이다 —
`담당자가 그 링크를 보낸 것은 이달 들어 벌써 열한 번째였다.` ·
`하지만 막상 직원들이 쓰기 시작하자 첫 주부터 바로 문제가 발생했다.`
짧은 문장 자체가 아니라 **문단 전체가 짧은 문장의 나열**인 것이 문제다.

### 번역투 목록 (이번에 실제로 걸린 것)

| ✕ | 무엇이 문제였나 | ✓ |
|---|---|---|
| `이번 달에만 같은 링크를 열한 번 붙였다` | `N번 V했다`로 횟수를 세는 영어 구문 · `링크를 붙이다`는 paste 직역 | `이달 들어 열한 번째다` |
| `~하는 사람, ~하는 사람, ~하는 사람이 매주 온다` | 명사구를 쌓아 나열 | `~하기도 하고, ~하기도 하고, ~하기도 한다` |
| `전 직원이 쓰기로 정해진다` | 피동 | `쓰기로 결정이 난다` |
| `회의에서 이것을 보여 주자` | 흐린 지시 | `회의에서 보여 주자` |
| `~것을 만들어 달라는 이야기다` | `~것이다` 계열 번역투 | `~프로그램을 만들어 달라고 한다` |
| `답이 맞다` | *The answer is correct.* 직역. 한국어는 상태가 아니라 **동작**으로 쓴다 | `제대로 답한다` |
| `첫 주에 네 번 깨진다` | *it breaks four times* 직역. 횟수 세기 + `깨지다` 오용 | `첫 주부터 바로 문제가 발생했다` |
| `개발팀에 부탁을 넣는다` | `요청을 넣는다`는 쓰지만 `부탁을 넣는다`는 안 쓴다 | `개발팀을 찾아간다` |

`이것을 환각이라고 부른다`처럼 **이름을 붙이는 구문의 `이것을`은 정상이다.**

**영어의 be동사 서술을 명사+형용사로 그대로 옮기지 않는다.** 한국어는 동사로 끌고 간다.
`답이 맞다` → `제대로 답한다`, `결과가 좋다` → `잘 나온다`. 주어를 세우고 상태를 붙이는 문장이
연달아 나오면 원문이 영어였던 것처럼 읽힌다.

**`깨지다`는 규칙에만 쓴다.** `R2를 깨는 상황` ✓ · `통제가 깨진다` ✓ 는 맞지만,
시스템이나 서비스를 주어로 `네 번 깨진다`고 쓰면 *break* 직역이다.
고침은 `하지만 막상 직원들이 쓰기 시작하자 첫 주부터 바로 문제가 발생했다`다.
여기 한때 `네 가지 문제가 드러난다`가 적혀 있었는데 그건 네 번 고치는 중간에 나온 말이고
지금은 폐기됐다 (아래 「네 번 고친 한 문장」).

## 7. 서사의 시제와 주어

**장면은 과거형, 설명은 현재형.** 1장 도입을 전부 현재형(`묻는다 · 짜 본다 · 답한다`)으로 썼다가
통째로 지적받았다. 한국어 산문은 지난 일을 과거형으로 쓴다. 현재형 서술은 영어 present-tense
내러티브를 그대로 옮길 때 나온다. 이 책의 **다른 장은 이미 전부 과거형이었다**
(`답했다` · `빠뜨렸고` · `응답했다` · `맡겼다`). 1장만 어긋나 있었다.

```
✕  직원이 총무팀에 묻는다. 담당자가 링크를 보내 준다. 코드를 짜 본다. 제대로 답한다.
✓  직원이 총무팀에 물었다. 담당자는 링크를 보내 줬다. 코드를 짰다. 그런데 제대로 답했다.
```

원칙을 설명하는 절은 현재형이 맞다 (`~로 나뉜다` · `~를 검사한다`). 한 장 안에서
**장면은 과거, 원칙은 현재**로 갈리는 것이 정상이고, 그 경계가 흐려지면 어색해진다.

**한 문단 안에서 그 경계를 잘못 그으면 바로 걸린다.** 아래는 실제로 지적받은 것이다.

```
✕  모델은 “…”라고 답했다. 틀린 데가 없다. 다만 모델이 한울연구소를 알아서 맞힌 것은 아니다.
      └ 과거          └ 현재(장면인데)      └ 만들어 쓴 연어

✓  모델은 “…”라고 답했다. 틀린 데가 없었다. 그런데 이 모델이 한울연구소를 아는 것은 아니다.
      └ 과거          └ 과거(그때 일)      └ 현재(언제나 참인 원칙) ✓
```

`알아서 맞히다`처럼 **동사를 둘 겹쳐 만든 말**은 대개 어색하다(§3). 하나로 줄이고 흔한 쪽을 택한다.

**2026-09-21에 같은 자리가 또 둘 나왔다** — `직원에게는 … 당연한 되물음이다` · `답하기 곤란한
질문이다`. 둘 다 앞 문장이 과거형 장면이고 뒤 문장이 현재형 원칙이라, 가운데 낀 판단문만 과거로
내리면 경계가 선다. **장면과 원칙 사이의 한 문장이 이 갈래의 상습 자리다.**

### `A의 N 가지 B` — A가 B를 소유하지 않으면 영어 직역이다

`데모의 네 가지 실패`는 *four failures of the demo* 직역이다. 데모가 실패를 가지고 있는 것이 아니다.
**소유가 아니면 `의`를 빼고 수식이나 서술로 푼다.** 수사가 붙은 꼴(`네 번의 실패`)은 §2에
따로 적었다 — 이 절에 원리만 있고 검사가 없어서 2026-09-19에 같은 부류를 한 번 놓쳤다.

**갈라지는 기준은 「소유」가 아니라 「A가 B로 이루어지는가」다 (2026-09-20에 고쳤다).**
이 절은 원래 `답변의 다섯 상태`를 자연스러운 예로 적어 뒀는데, 저자가 읽다가 그 절 제목을
짚었다. **답변은 다섯 상태를 가진 것이 아니라 그 다섯 중 하나다.** 담는 쪽이 아니라 담기는
쪽을 `A의`로 세우면 어색해진다.

| 판정 | 제목 | 왜 |
|---|---|---|
| ✕ | `답변의 다섯 상태` → `다섯 가지 답변 상태` | 답변이 다섯 중 하나라서 담는 쪽이 아니다 |
| ✕ | `결과의 여섯 상태` → `여섯 가지 결과 상태` | 같은 자리. 한 곳을 고치면 책 전체를 훑는다 |
| ✓ | `문맥 실패의 여섯 유형` | 문맥 실패가 여섯 유형으로 나뉜다 |
| ✓ | `인용 검증의 세 단계` · `지시의 네 요소` · `환각의 네 갈래` | 전부 부분–전체다 |
| ✓ | `입력의 세 출처` | 진짜 소유 관계다 |

**그림 제목도 같이 고친다.** `AnswerStates`는 본문이 `답변`이라 부르는 것을 `응답의 다섯 상태`로
적고 있었다. 절 제목·그림 제목·본문이 같은 말을 써야 한다(§24).

| ✕ | ✓ |
|---|---|
| `데모의 네 가지 실패` | `네 가지 문제` |
| `걸린 순서대로 적는다` | `문제가 터진 순서대로 적는다` (무엇이 걸렸는지가 없었다) |

관형절의 머리명사를 빼먹는 것도 같은 부류다. `터진 순서` · `걸린 순서`는 **무엇이** 그랬는지를
앞 문단에서 끌어와야 읽히는데, 그 사이에 표현을 바꾸면 연결이 끊긴다.

**무생물을 주어로 세우고 자동사를 붙이지 않는다.** 영어는 `problems surface`가 자연스럽지만
한국어는 사람이나 상황을 주어로 놓거나 주어를 아예 뺀다.

| ✕ | ✓ |
|---|---|
| `첫 주에 네 가지 문제가 드러난다` | `막상 직원들이 쓰기 시작하자 첫 주에만 네 군데서 걸렸다` |
| `답이 흔들리지 않아서` | `몇 번 더 물어도 마찬가지여서` |
| `직원들에게 열어 준 첫 주에` | `직원들이 쓰기 시작하자` |
| `전 직원이 쓰기로 결정이 난다` | `전 직원이 쓰기로 했다` |

`답이 흔들리다` · `링크를 붙이다` · `직원들에게 열어 주다`는 전부 **만들어 쓴 연어**다(§3).
뜻은 통하지만 아무도 그렇게 안 쓴다. 확신이 없으면 사람을 주어로 놓고 흔한 동사를 쓴다.

**명사절을 주어로 세우면 거의 늘 걸린다.** `왜 ~는지가` · `무엇이 ~했는지가`를 주어 자리에
놓는 것은 영어 that절 직역이다. 2026-09-19에 장 끝 문단 열일곱 개를 한 번에 쓰면서
아래 여섯 개가 나왔다. **전부 이 문서에 이미 있던 규칙을 어긴 것이다.**

| ✕ | 무엇이 주어였나 | ✓ |
|---|---|---|
| `이제 그 로그에 왜 끊겼는지가 함께 남는다` | 명사절 | `개발팀은 같은 로그에서 끊긴 이유까지 본다` |
| `문서 본문만 보고는 답이 안 나오는 질문` | `답` | `봇이 문서 본문만 보고는 답할 수 없는 질문` |
| `9월판이 검색에서 내려가지 않았다` | `9월판` + 만든 연어 | `9월판이 그대로 검색에 남아 있었다` |
| `그 화면은 R01~R04를 그대로 내보냈다` | 화면은 내보내는 주체가 아니다 | `그대로 보여 줬다` |
| `그 티켓이 1위로 온다` | 만든 연어 | `1위에 오른다` (본문이 이미 쓰는 짝) |
| `말은 시키지 말자는 쪽으로 정리됐다` | 피동 + 주체 없음 | `개발팀은 아직 학습을 시키지 않기로 했다` |

**`남다`는 이 갈래의 단골이다.** 책 전체 25곳을 훑어 보니 `기록을 남긴다`(사람이 주어) ·
`이전 문서가 검색에 남아 있다`(구체물) · `충돌은 남는다`(국어에 원래 있는 짝)는 전부 정상이고,
걸린 것은 **명사절을 주어로 세운 한 곳뿐**이었다. 낱말을 금지하지 말고 **주어가 무엇인지**를 본다.

## 8. 주어를 함부로 빼지 않는다

**무생물 주어를 피하라는 말(§7)을 주어를 빼라는 말로 잘못 옮겼다가 다시 지적받았다.**
한국어가 주어를 생략하는 것은 **문맥에서 복원될 때뿐**이다. 행위자가 문장마다 바뀌는
서사에서 주어를 빼면 누가 한 일인지 사라진다.

```
✕  담당자는 링크를 보내 줬다. 이달 들어 열한 번째였다.        ← 뭐가 열한 번째인가
✓  담당자는 링크를 보내 줬다. 담당자가 그 링크를 보낸 것은 이달 들어 열한 번째였다.

✕  개발팀은 그날 오후에 코드를 짜 봤다. … 그런데 제대로 답했다.  ← 개발팀이 답했다는 말이 된다
✓  개발팀은 그날 오후에 코드를 짜 봤다. … 그런데 이 코드가 제대로 답을 내놨다.
```

| ✕ | 무엇이 문제였나 | ✓ |
|---|---|---|
| `개발팀의 한 사람이` | *one of the developers* 직역 | `개발팀은` |
| `경로가 아니라 한도를` | 앞 문장의 `링크`를 가리키는 것처럼 읽힘 | `신청 방법 대신 한도를` |
| `네 군데서 걸렸다` | `걸리다`의 주어가 없다 | `문제가 네 가지 나왔다` |
| `모두 지어낸 값이라 실제 규정으로 읽으면 안 된다` | 뒷말이 군더더기 | `모두 가상의 값이다` |
| `문서를 모두에게 붙였다` | `붙이다`는 **붙일 자리**를 받지 받는 사람을 못 받는다 | `누가 묻든 전부 프롬프트에 넣었다` |
| `데모에 붙여 둔 파일` | 데모는 붙일 표면이 아니다 | `데모에 넣어 둔 파일` |
| `모르는 자리를 비워 두지 않고 그럴듯한 문장으로 메운다` | *fill in the blank* 직역 | `모를 때도 모른다고 하지 않고 그럴듯한 문장을 만들어 낸다` |

`프롬프트에 붙이다` · `질문 뒤에 붙이다` · `접두사를 붙이다` · `이어 붙이다`는 전부 맞는 말이다.
**어디에** 붙는지가 분명하면 쓰고, 사람이나 추상물이 자리에 오면 `넣다` · `준다`로 바꾼다.

### 그 밖에 이번에 고친 것

| ✕ | ✓ | 왜 |
|---|---|---|
| `틀린 데가 없었다` | `정확했다` | 부정으로 둘러 말하지 말고 바로 단언한다 |
| `모델은 방금 …읽고 답했을 뿐이다` | `모델은 **단지** 방금 …답했을 뿐이다` | `단지 … 뿐이다`는 짝을 이루는 호응이다. 앞짝이 빠지면 문장이 헐겁다 |
| `봇의 일` (표 열 이름) | `봇이 하는 일` | 명사구는 무엇을 적는 칸인지 흐리다. 옆 열 `직원의 요청`과 짝도 안 맞았다 |
| `코드를 짜 봤다` | `그 프로그램을 만들었다` | 무엇을 만들었는지가 빠졌다 |
| `이 코드가 제대로 답을 내놨다` | `이 프로그램이 잘 동작했다` | 답한 것은 코드가 아니라 봇이다 |
| `분량은 한 화면에 들어갔다` | (지운다) | 무슨 말인지 전달이 안 된다 |
| `맞는 답이다` · `답이 맞다` | `정확했다` | be동사 직역. `틀린 데가 없다`도 에두른 부정이라 다시 뒤집혔다 |

**서사 문단을 넘기기 전에 문장마다 “누가”를 물어본다.** 답이 안 나오면 주어를 적는다.

## 9. 부정을 겹치지 않는다

한 문장에 `없다 · 않다 · 못하다 · 아니다`가 셋 이상이면 읽는 쪽이 셈을 해야 한다.
긍정으로 바꿀 수 있는 자리를 먼저 바꾼다.

```
✕  근거가 없으면 없다고 말하고, 읽을 권한이 없는 문서는 있다는 사실도 말하지 않는다.
      └ 없다 ×3 + 있다 ×1이 한 문장에

✓  근거를 찾지 못하면 봇은 모른다고 답한다.
   사용자가 읽을 수 없는 문서라면 내용은 물론 그런 문서가 있다는 사실조차 알리지 않는다.
```

**말하는 동사의 주어는 사람이나 시스템이다.** 위 ✕에서 `말하지 않는` 주어가 `문서`가 돼 있었다.
앞 문장에 `봇은`을 세우면 두 문장이 같은 주어를 이어 받는다.

**규칙 두 개를 쉼표로 이어 붙이지 않는다.** 근거가 없을 때의 처리와 권한이 없을 때의 처리는
별개 규칙이라 한 문장에 넣으면 둘 다 흐려진다. 문장을 나눈다.

## 10. 사건을 미리 세지 않는다

`첫 주 만에 문제가 네 가지 나왔다`는 *four problems came up* 직역이다. 한국어 서사는
사건을 먼저 세어 보여 주지 않고 그냥 터뜨린다. 개수는 바로 뒤 소제목(`## 데모의 네 가지 실패`)이
말하므로 본문에서 또 셀 이유도 없다.

| ✕ | ✓ |
|---|---|
| `첫 주 만에 문제가 네 가지 나왔다` | `하지만 막상 직원들이 쓰기 시작하자 첫 주부터 바로 문제가 발생했다` |

**`문제가 발생하다`는 굳은 연어라 그냥 쓴다.** §7의 “무생물 주어 + 자동사” 규칙을
`발생`까지 넓혔다가 이 문장이 걸려서 되돌렸다. 번역투로 보는 것은 `문제가 드러나다` ·
`문제가 나타나다`처럼 **영어 동사를 옮긴 자리**이고, 국어에 원래 있던 짝까지 막으면 안 된다.
규칙을 만들 때 **그 표현이 한국어에 원래 있던 말인지** 먼저 본다.

### 네 번 고친 한 문장

같은 자리를 네 번 고쳤고 그때마다 고침이 다음 차례의 ✕가 됐다. **중간 판정을 규칙으로 읽지 말 것.**

```
✕ 첫 주에 네 번 깨진다          → 네 가지 문제가 드러난다      (폐기)
✕ 네 가지 문제가 드러난다       → 첫 주에만 네 군데서 걸렸다   (폐기)
✕ 네 군데서 걸렸다              → 문제가 네 가지 나왔다        (폐기)
✕ 문제가 네 가지 나왔다         → 첫 주부터 바로 문제가 발생했다  ← 이것이 마지막 판정
```

`드러나다`는 지금도 `check-prose.py`가 번역투로 잡는다. 중간 고침이 문서 여기저기에 ✓로
남아 있으면 다음 사람이 그중 하나를 답으로 쓴다. **✓를 적을 때는 그것이 마지막 판정인지 본다.**

### 절 제목도 세지 않는다 (2026-09-20 저자 지시)

저자가 물었다. **"애초에 몇 가지인지 꼭 말을 해야하는거야? 일반적인 책에서는 이런식으로
몇 가지인지는 잘 말 안할텐데."** 이 절의 원칙을 산문에만 걸고 절 제목에는 안 걸고 있어서
『AI 엔지니어링』에 세는 제목이 **19개** 쌓여 있었다.

**개수를 이름에 박아 넣지 않는다. 제목이든 산문이든 마찬가지다.** 저자가 이어서 짚었다 —
`일곱 가지 요구사항` → **"너무 길어 그냥 요구사항 이라고만 써."** 한 번 세고 나면
그 뒤로는 이름으로 부른다.

| | |
|---|---|
| ✕ 이름에 개수가 박혀 있다 | `일곱 가지 요구사항을 하나같이 …로 썼다` · `요구사항 일곱 가지 가운데 마지막인 R7` · `일곱 자리에서 따로 채점하고` |
| ✓ 문장이 실제로 센다 | `개발팀이 네 가지 문제를 놓고 다시 모였다` · `넷을 하나씩 들여다보기로 했다` |

**✕ 열에 `##`을 붙여 뒀다.** 이 표는 **제목에서만** 금지다 — `개발팀이 네 가지 문제를 놓고
다시 모였다`처럼 산문에서 세는 것은 정상이라, 백틱을 두르면 `check-rules.py`가 본문을
잡는다(2026-09-20에 실제로 그렇게 걸렸다). 검사는 `check-book.py`의 「제목이 개수를 센다」가 맡는다.

**제목은 몇 개인지가 아니라 무엇을 하는 자리인지를 말한다.** 개수는 아래 표나 번호가
어차피 보여 준다.

| ✕ | ✓ |
|---|---|
| ## 네 가지 문제 | `첫 주의 실패` |
| ## 다섯 가지 답변 상태 | `답하지 못할 때` |
| ## 일곱 가지 요구사항 | `요구사항으로 옮기기` |
| ## 세 단계의 성공 | `전송·생성·업무` (이름을 그대로 쓴다) |
| ## 지시의 네 요소 | `작업·문맥·예시·제약` |
| ## 문맥 실패의 여섯 유형 | `문맥이 실패하는 자리` |
| ## 네 가지 한도 | `루프를 멈추는 한도` |
| ## 프롬프트 주입의 세 겹 | `프롬프트 주입 막기` |
| ## 다섯 질문의 실측 · ## 여섯 질문의 실측 · ## 네 질문의 실측 | `가상 문서로 재 본 점수` · `두 검색기를 같은 질문으로` · `실제 문서로 돌려 본 기록` |

**세 개가 `N 질문의 실측`으로 똑같았다.** 개수만 다르고 제목이 같으면 목차에서 구별이 안 된다.
개수를 빼면 그 절이 실제로 무엇을 쟀는지를 쓸 수밖에 없고, 그래서 셋이 갈린다.

`한 단계의 순서`는 그대로 뒀다 — `한`은 개수가 아니라 낱개를 가리킨다.
`check-book.py`의 「제목이 개수를 센다」가 이 갈래를 막는다.

## 11. 기계 용어로 서사 비트를 처리하지 않는다

`동작했다` · `수행했다` · `처리했다`는 사양서의 말이다. 장면에서는 **그 사물이 실제로 하는 일의 동사**를
쓴다. 봇은 답하고, 검색기는 찾아내고, 저장소는 돌려준다.

| ✕ | ✓ |
|---|---|
| `질문을 바꿔 가며 몇 번 더 시켜 봐도 마찬가지였다` | `질문을 이리저리 바꿔 물어도 묻는 의도에 맞게 대답했다` |

**이 규칙을 `동작했다`에까지 밀지 않는다.** 한때 `이 프로그램이 제대로 동작했다` ✕ →
`곧잘 답했다` ✓가 여기 있었지만 2026-09-19에 저자가 `예상외로 잘 동작했다`로 되돌렸다(§5).
`수행했다` · `처리했다`처럼 **국어에 없던 자리에 들어온 말**만 걸러 내고, `동작하다`처럼
이미 굳어 쓰이는 말은 둔다.

**물건을 가리키는 말을 글에 붙이지 않는다.** `덩어리`는 고기·흙에 쓰는 말이라 텍스트에 붙으면
어색하다. 입력·출력처럼 형체가 없는 것은 `모양` · `하나로` 같은 말로 가리킨다.

| ✕ | ✓ |
|---|---|
| `모델이 받은 입력은 이런 덩어리였다` | `모델이 받은 입력은 이런 모양이었다` |
| `문서와 질문을 한 덩어리로 묶어` | `문서와 질문을 하나로 묶어` |

`마찬가지였다` · `그랬다` · `같았다`로 뭉개지 말고 **무엇이 어떠했는지 적는다.** 대용 표현은
앞 문장을 되짚게 만들어서 읽는 속도를 떨어뜨린다. 프로그램에 `시키다`를 쓰는 것도 어색하다 —
질문하는 물건에는 `묻다`가 맞다.

---

## 12. 인과가 있으면 인과를 적는다

가장 여러 번 놓친 자리다. 앞 문장이 **결과**, 뒤 문장이 **원인**인데 그 관계를 안 적으면
사실 두 개가 나란히 놓인 것처럼 읽힌다. 뒤 문장을 `~기 때문이다`로 닫거나 앞에 `그래서`를 붙인다.

| ✕ | ✓ |
|---|---|
| `그 방법으로는 안 된다. 입력 길이에 상한이 있고 비용도 오른다.` | `… 안 된다. 입력 길이에 상한이 있고, 비용도 오르기 때문이다.` |
| `데모는 문서를 모두에게 붙였다. 권한은 모델이 판단할 것이 아니다.` | `데모가 권한과 상관없이 모두에게 붙였기 때문이다. 애초에 권한은 …` |
| `존재도 알리지 않는다. “볼 수 없습니다”라는 답이 있다는 사실을 알려 준다.` | `… 알려 주기 때문이다.` |
| `이 구분이 책 전체의 토대다. 모델을 고치는 대신 …` | `… 토대다. 그래서 모델을 고치는 대신 …` |

**굵은 머리말로 사건을 던진 문단은 바로 다음 문장에서 그 사건을 설명한다.**
`**…라고 답했다.** 그런데 등록된 문서에는 그런 조항이 없다.` — `그런데`가 없으면
사건과 설명이 따로 논다.

**이 검사는 자동화가 안 된다.** 문단마다 인접한 두 문장 사이에 `그래서 · 그런데 · 하지만 ·
때문이다` 중 무엇이 들어가야 하는지 직접 물어본다. 아무것도 안 들어가는 자리가 정상인 경우도
있지만, 세 문장 연속으로 아무 관계도 표시되지 않으면 다시 본다.

**다만 장면 문단에만 건다.** 2026-09-19에 "세 문장 연속"을 23개 파일에 기계로 돌리니 **94곳**이
나왔는데 대부분 규칙을 늘어놓은 설명 문단이었다. `A한다. B한다. C한다.`로 나열하는 것이
거기서는 맞고, §9가 오히려 잇지 말라고 한다. **과거형 문단으로 좁히면 0곳이다.**
§6의 「끊긴 문단」과 같은 이야기라 `check-prose.py`도 같은 범위로 돌린다.

## 13. 에두르지 않는다

**부정으로 돌려 말하거나 명사로 받아 놓으면 문장이 한 겹 멀어진다.** 뜻은 통하고 번역투 검사도
통과하는데, 저자가 읽으면 “이상한 문장”으로 걸린다. 1장에서 한 번에 열두 곳이 걸렸다.

### 부정으로 에두른 자리

| ✕ | ✓ |
|---|---|
| `엉뚱한 소리를 하지 않았다` | `묻는 의도에 맞게 대답했다` |
| `질문이 매번 같지도 않았다` | `직원마다 알고 싶어 하는 대목이 달랐다` |
| `어느 문서를 골라 넣을지는 생각할 것도 없었다` | `폴더에 있는 것을 전부 넣으면 그만이었다` |
| `오히려 반대할 이유를 대기가 어려웠다` | `반대하는 사람은 없었다` |
| `예제 문서는 본문만 저장하지 않는다` | `본문에 네 가지를 더해 다섯 필드로 저장한다` |

**§9의 “부정을 겹치지 않는다”와 다른 이야기다.** 그쪽은 한 문장에 부정이 셋 이상이라
셈을 해야 하는 경우이고, 여기는 **부정이 하나뿐이어도** 그것이 평서문을 피해 간 자리다.
`~하지 않았다`를 보면 **그래서 무엇을 했는지**를 물어보고, 답이 나오면 그 답으로 바꾼다.
`본문만 저장하지 않는다`는 “본문은 저장 안 한다”로도 읽혀서 뜻까지 흐렸다.

### 명사로 받아 놓은 자리

| ✕ | ✓ |
|---|---|
| `20만 원이라고 답했을 때가 프롬프트와 모델을 볼 차례다` | `답했다면 그때 프롬프트와 모델을 본다` |
| `… 단계별 시간이 기록의 시작이다` | `… 단계별 시간부터 기록한다` |
| `대신 검색이 들어오면서 볼 곳이 하나 늘었다` | `확인할 것이 하나 늘었다` |

`~할 차례다` · `~의 시작이다` · `~할 자리다`는 **동작을 명사로 바꿔 놓고 서술어 자리에
`이다`를 세운 꼴**이다. 동사로 끝내면 한 겹이 사라진다.

### 그 밖에 같이 걸린 것

| ✕ | 무엇이 문제였나 | ✓ |
|---|---|---|
| `파일을 갈아 끼우면 될 것 같지만 한 겹이 더 있다` | 비유 | `여기에는 문제가 하나 더 있다` |
| `데모가 누가 묻든 가진 문서를 전부` | 무생물 소유 | `폴더에 있는 문서를 전부` |
| `권한은 모델이 판단할 것이 아니다` | `것` | `판단할 몫이 아니다` |
| `문서는 … 존재도 알리지 않는다` | 말하는 동사의 주어가 물건(§9) | `문서라면 봇은 … 사실까지 숨긴다` |
| `그 문장과 실제 상태를 아무도 잇지 않았기 때문이다` | 만들어 쓴 연어(§3) | `아무도 연결하지 않았기 때문이다` |

`잇다`는 §3에 이미 있던 항목인데 1장에 한 곳이 남아 있었다. **한 곳을 고치면 grep으로 파일
전체를 훑는다**(SKILL.md §1). 다른 장에도 일곱 곳이 남아 있어 `check-prose.py`에 넣었다.

## 14. 장면과 장면 사이를 건너뛰지 않는다

**저자의 말 — “소설이라고 생각하고 모든 맥락이 이어지게끔 써야 한다. 갑자기 맥락을
뛰어넘으면 안 된다.”** §6(단문 나열)를 고치고 나서도 남은 문제가 이것이었다. 문장은
이어졌는데 **박자와 박자 사이**가 비어 있었다.

| 건너뛴 자리 | 빠져 있던 것 | 넣은 다리 |
|---|---|---|
| `열한 번째였다` → `질문이 매번 달랐다` | 링크를 열한 번 보낸 것이 왜 해결이 아닌지 | `링크 하나로 끝나는 질문이라면 열한 번이든 스무 번이든 다시 보내면 그만이었다. 그런데 …` |
| `규정을 다시 펴 봐야 했다` → `개발팀을 찾아갔다` | 참다가 왜 지금 움직였는지 | `이런 질문이 몇 달째 줄지 않자 총무팀도 방법을 바꿔 보기로 했다` |
| 요청 → `그날 오후에 착수했다` | 개발팀이 왜 바로 시작했는지 | `개발팀도 마침 언어 모델을 사내 업무에 써 볼 기회를 찾고 있던 참이라 …` |
| 담당자 시연 → `회의에서 보여 주자` | 누가 이 결과를 회의로 옮겼는지 | `담당자가 이 정도면 쓰겠다고 하자 개발팀은 그다음 주 회의에 이 화면을 그대로 들고 갔다` |
| 공지 → `첫 주부터 문제가 발생했다` | 데모와 무엇이 달라졌는지 | `데모 때와 같은 화면이었지만 묻는 사람은 담당자 한 명에서 전 직원으로 늘어 있었다` |

**다리는 인과 한 문장이다.** “A 다음에 B가 일어났다”가 아니라 **“누가 무엇을 보고 B를
했는지”**를 적는다. §8의 “문장마다 누가를 물어본다”를 **문단 사이에도** 적용하는 것이다.

**한 문장으로 끝난 문단은 박자가 눌린 것이다.** `개발팀이 회의에서 결과를 보여 주자 다음
분기부터 전 직원이 쓰기로 했다` 한 문장에 시연·결정·일정 세 박자가 들어 있었다.
`check-prose.py`가 **짧은 장면 문단(과거형 3문장 이하)이 세 번 연속**되면 잡는다.

**서사 문단 사이에 설명 블록을 끼우지 않는다.** 가상 회사 고지가 절정 문장
(`첫 주부터 바로 문제가 발생했다`) 바로 뒤에 있어서 박자를 죽이고 있었다. 장 맨 앞으로 옮기고
`>` 인용문으로 바꿔 본문과 등록을 분리했다. 표도 마찬가지라 `## 업무 봇`의 표 앞에
`직원들이 봇에 던진 요청은 크게 세 가지였다` 한 줄을 넣어 서사에서 표로 넘어가게 했다.

**“풀어 써 달라”는 요청은 분량 규칙보다 앞선다.** SKILL.md §7의 `원문의 1/3~1/2`은
초고를 줄일 때의 기준이다. 저자가 이야기를 풀라고 하면 **다리를 놓는 문장은 늘어나는 것이
맞다.** 늘릴 자리는 인과와 장면이지 설명이 아니다.

### 절을 여닫는 자리는 줄이지 말고 푼다 (2026-09-20 저자 지시)

저자가 같은 말을 두 번 했다. **"설명이 너무 짧아"** · **"마무리 말이 이상해. 무슨 말인지
모르겠어. 설명을 더 풀어서 해야지."** 둘 다 절을 여는 문단과 장을 닫는 문단이었다.

**짧은 문장은 힘이 있지만, 그 힘은 앞에서 깔아 준 것이 있을 때만 난다.**
깔아 줄 것이 없는데 짧으면 그냥 안 읽힌다.

| 어디 | ✕ | 무엇이 없었나 |
|---|---|---|
| 절 도입 | `고작 나흘 사이에 일어난 일이다.` (이 한 문장이 전부) | 공지가 나간 뒤 무슨 일이 있었는지, 왜 처음엔 몰랐는지 |
| 장 결어 | `이 일곱 가지 요구사항을 지키는 데 드는 것이 나머지 전부다.` | **무엇의** 나머지인지. 일곱 가지가 실제로 어떤 일인지 |
| 장 마지막 장면 | `이달 들어 열한 번이던 링크는 그래도 줄었다.` (요약 두 줄로 끝) | 담당자가 실제로 봇을 쓰는 장면, 날짜를 묻고 개발팀이 못 대답하는 순간 |

**결어를 풀다가 새 번역투를 세 번 만들었다.** 고친 판을 저자가 다시 짚은 것이 이렇다.

| ✕ | 무엇이 걸렸나 | ✓ |
|---|---|---|
| `데모를 만드는 데는 오후 한나절이 들었다` | 시간은 걸리는 것이지 드는 것이 아니다(§3). `~하는 데는`으로 명사구를 주어에 세웠다 | `데모는 오후 한나절 만에 나왔다` |
| `그 한나절에 없던 것이 이 일곱 가지 요구사항이다` | 명사절 주어 + `이다`. 시간이 무엇을 담고 있다는 말이 성립하지 않는다 | (지우고 할 일을 직접 적었다) |
| `담당자가 직원의 질문을 대신 받지 않아도 되는 날은 그 뒤에 있었다` | *that day was still ahead* 직역. `받지 않아도 되는`으로 부정을 두 겹 씌웠다 | `직원이 담당자를 거치지 않고 봇에게 직접 묻기까지는 아직 멀었다` |
| `개발팀은 날짜를 대지 못했다` | 날짜는 대는 것이 아니라 **잡는** 것이다(§3). 게다가 `개발팀은 선뜻 숫자를 대지 못했다`(6부)와 같은 틀이 장을 건너뛰어 두 번 나왔다 | `개발팀은 날짜를 잡지 못했다` · `개발팀은 선뜻 대답하지 못했다` |
| `얼마나 되는 일인지 아직 아무도 해 보지 않았다` | **`얼마나 ~인지`는 `알다`로 받아야 한다.** `해 보다`로 받아 주술이 어긋났다(§15) | `얼마나 되는 일인지 아직 아무도 알 수 없었다` |
| `봇에게 직접 묻기까지는 아직 멀었다` | **관형절의 머리명사 `날`을 빼먹었다.** 무엇이 먼 것인지가 문장에 없다(§7 「관형절의 머리명사를 빼먹는 것도 같은 부류다」) | `봇에게 바로 묻는 날은 아직 멀었다` |

**같은 문장을 네 번 고쳤다.** `나머지 전부다` → `그 뒤에 있었다` → `묻기까지는 아직 멀었다` →
`묻는 날은 아직 멀었다`. 고칠 때마다 다른 갈래가 하나씩 남았다 —
가리키는 대상 없음 → 직역 + 이중 부정 → 머리명사 누락. **장을 닫는 한 문장이 제일 많이 틀린다.**

**풀어 쓰라는 지적을 받고 늘린 문장이 다시 번역투가 됐다.** 길게 쓸수록 명사구와 이중 부정이 들어온다 —
푼 다음에 §20의 네 물음을 한 번 더 돌린다.

고친 결어는 넷을 이름으로 풀어 적고 나서 그 대비를 세운다 — 리비전과 시행일, 읽을 권한,
근거 검사, 접수한 말과 실제 티켓. **넷을 적고 나서야 `한나절`과의 대비가 크기를 갖는다.**

`check-prose.py`의 「절 도입이 한 문장뿐」이 앞쪽 갈래를 잡는다. 뒤쪽은 눈으로 본다 —
결어가 짧은 것 자체는 옳고, **가리키는 대상이 문면에 없을 때**가 틀린 것이라 정규식으로 안 갈린다.

## 15. 조사와 리듬

**이 문서의 나머지가 빼기라면 이 절은 더하기다.** 번역투를 다 걷어내도 문장이 밋밋하면 읽히지
않는데, 그 밋밋함은 대개 조사·서술어·호흡 세 가지에서 온다. §5가 처방한 화자 부사는 증상을
덮은 것이고 여기가 그 기전이다. 예문은 전부 『개발자를 위한 AI 엔지니어링』 1장에서 뽑았다.

### 은·는과 이·가

**처음 나오는 사람은 `이/가`, 이미 자리 잡은 사람은 `은/는`이다.**

```
✓  한울연구소에 갓 들어온 직원이 총무팀에 물었다. 담당자는 규정 문서를 찾아 링크를 보내 줬다.
        └ 첫 등장                                 └ 이 장의 화제로 세운다

✕  한울연구소에 갓 들어온 직원은 총무팀에 물었다.
        └ 독자가 모르는 사람을 이미 아는 사람처럼 가리킨다
```

**관형절·종속절 안의 주어는 `이/가`다.** `담당자가 그 링크를 보낸 것은 이달 들어 벌써
열한 번째였다`에서 안쪽 주어를 `담당자는`으로 바꾸면 한 문장이 화제를 두 번 세워 어긋난다.

**대조하는 자리에는 `은/는`을 쓴다.** `반대하는 사람은 없었다`는 다른 반응과 견주는 말이고,
`반대하는 사람이 없었다`로 쓰면 그냥 사실 보고가 된다.

**화제를 옮길 때 `은/는`으로 새 인물을 세운다.** `개발팀은 그날 오후에 바로 작업에 착수했다`가
문단을 여는 것은 여기서 화제가 담당자에서 개발팀으로 넘어가기 때문이다. 문단이 바뀌는데
주어가 계속 `이/가`면 누구 이야기인지 흐려진다.

### 서술어 자리의 맨 명사에 쿠션을 준다 (2026-09-20 저자 지시)

저자가 `모델이 아니라 모델에게 넘기는 입력이다`를 두고 **"쿠션어, 같은 명사라도 좀 더
부드럽게 읽히게"**라고 했다. 기술명사 하나를 그대로 서술어 자리에 세우면 읽는 호흡이
거기서 뚝 끊긴다. **한 글자 붙이거나 동사로 푼다.**

| ✕ | ✓ | 어떻게 |
|---|---|---|
| `손댈 곳은 … 넘기는 입력이다` | `… 넘기는 입력 쪽이다` | `쪽`을 붙인다 |
| `데모는 네 단계다` | `데모는 네 단계뿐이다` | `뿐`으로 범위를 닫는다 |
| `세는 횟수도 비용이다` | `세는 횟수도 비용에 들어간다` | 동사로 푼다 |
| `다운로드와 추론은 별도 단계다` | `다운로드와 추론은 서로 다른 단계로 나뉜다` | 동사로 푼다 |
| `저장소 파일도 외부 입력이다` | `저장소 파일도 외부 입력에 들어간다` | 동사로 푼다 |

쿠션으로 쓰는 말은 `쪽` · `편` · `자리` · `뿐` · `셈` 정도다. `부분`도 저자가 든 예다.

**정의문과 장을 닫는 한 방은 그대로 둔다.** `코사인 유사도는 내적을 두 길이의 곱으로 나눈
값이다`는 그 명사가 정의의 내용이라 쿠션이 필요 없고, `그 번호를 만든 것은 모델이 아니라
서버다` · `막는 것은 서버다`는 짧게 끊는 것이 목적이다.

### 서술어의 종류를 섞는다

§6은 `~다`로 끝나는 문장이 이어지면 번역 초고라고 적었는데, 한국어 평서문은 원래 다 `~다`로
끝난다. 단조로운 것은 종결형이 아니라 **서술어의 종류**다.

| 종류 | 1장의 예 | 하는 일 |
|---|---|---|
| 동사 | `질문을 받을 때마다 규정을 처음부터 다시 펴 봐야 했다` | 사건을 민다 |
| 계사 `이다` | `돌아온 문장을 화면에 띄우는 것이 전부였다` | 장면을 요약해 닫는다 |
| 존재 | `그 링크를 다시 보내던 담당자가 그 자리에 있었다` | 상태를 놓는다 |

동사로만 밀면 사건 보고서가 되고 `이다`로만 받으면 설명서가 된다. 1장 도입 열세 문장에서
동사와 계사가 다섯씩이다. **문단을 닫는 문장에 `이다`를 한 번 쓰고 나머지는 동사로 끝낸다.**

### 호흡은 평균이 아니라 분산이다

`SKILL.md` §5의 평균 31~42자는 **하한선**이다. 평균이 맞아도 한 문단 안 문장이 다 비슷한
길이면 밋밋하다. 1장 도입을 재면 이렇다.

```
문단1   26 · 44 · 34자              평균 35   표준편차  7   ← 일부러 끊은 첫 문단
문단2   44 · 26 · 60 · 36 · 67자    평균 47   표준편차 15
문단4   24 · 106 · 51자             평균 60   표준편차 34
문단6   50 · 30 · 13 · 86자         평균 45   표준편차 27
```

긴 문장 두셋 뒤에 짧은 문장 하나를 놓으면 그 짧은 문장이 박자를 찍는다 —
`반대하는 사람은 없었다`가 13자다. **표준편차가 10 아래면 그 문단을 다시 본다.**
첫 문단처럼 일부러 끊는 자리는 예외다.

### 호응을 짝으로 맞춘다

`단지 … 뿐이다` · `아무도 … 않았다` · `막상 … 하자`는 앞짝과 뒤짝이 함께 가는 말이다.
앞짝을 빠뜨리면 문장이 헐거워진다.

```
✕  모델은 방금 프롬프트에 붙여 준 두 문장을 읽고 답했을 뿐이다.
✓  모델은 단지 방금 프롬프트에 붙여 준 두 문장을 읽고 답했을 뿐이다.
```

**강조 조사도 고른다.** `사실도` → `사실조차`. 내용을 안 보여 주는 것은 당연하고 존재까지
감춘다는 것이 §9에서 다루는 그 규칙의 핵심이라, 그 강조를 `조차`가 맡는다.

### `~에 대해`는 목적격 조사로 직결한다 (A-1 · S1)

이 책에 0회로 유지되던 패턴인데 2026-09-18에 한 문장으로 처음 들어왔다가 바로 걸렸다.
`X에 대해 알다` → **`X를 알다`**. 조사 하나만 바꾸면 되므로 나머지 표현은 그대로 살린다.

```
✕  이 모델이 한울연구소의 내부 정책에 대해 원래부터 알고서 대답한 것은 아니다.
✓  이 모델이 한울연구소의 내부 정책을 원래부터 알고서 대답한 것은 아니다.
```

`~에 대해 논의하다` → `~를 논의하다`, `~에 대해 설명하다` → `~를 설명하다`도 같다.
`check-prose.py`가 잡으니 넘기기 전에 돌린다.

## 16. 연결어미 뒤 쉼표

`im-not-ai`의 `ending_comma_rate`로 재니 이 책이 43%, 그쪽 코퍼스 기준 **z +5.0**이었다.
한 문장에 다른 쉼표가 없고 앞 절이 34자 이하면 쉼표를 뺀다. **134곳을 지웠다.**

```
✕  어떤 직원은 신청 방법 대신 한도를 물었고, 어떤 직원은 작년 규정을 읽고 와서 되물었다.
✓  어떤 직원은 신청 방법 대신 한도를 물었고 어떤 직원은 작년 규정을 읽고 와서 되물었다.
```

**남기는 자리** — 세 항목 이상 나열(`A하고, B하고, C한다`), 앞 절이 긴 문장,
한 문장에 쉼표가 둘 이상이라 절 경계가 헷갈리는 자리. 그리고 **`-고` 뒤의 말이 앞 동사에
붙어 읽히는 자리**. 이건 자동 삭제로 세 곳을 망가뜨리고 나서야 알았다.

```
✕  근거가 없으면 없다고 말하고 읽을 권한이 없는 문서는 …   ← “말하고 읽을”이 한 덩어리
✓  근거가 없으면 없다고 말하고, 읽을 권한이 없는 문서는 …

✕  같은 조건으로 비교하고 평가를 통과한 범위에서만 …       ← “비교하고 평가를”이 한 덩어리
✓  같은 조건으로 비교하고, 평가를 통과한 범위에서만 …
```

일괄 치환 뒤에는 `[가-힣]{2,}고 [가-힣]+[을를는] `로 훑어 이 꼴을 눈으로 본다. 한글 맞춤법도 "문장의 연결 관계를
분명히 하고자 할 때" 쉼표를 허용하므로 **일괄 삭제는 하지 않는다.**

|---|---|
| `네 갈래로 묶으면 대체로 다 들어간다` | `운영체제가 하는 일은 크게 넷이다` |

```
✕  네 갈래로 묶으면 대체로 다 들어간다              ← 셀 수 있는데 안 셌다
✓  나머지 문서를 마저 붙이는 일만 남은 셈이었고      ← 회의에 앉은 사람들의 짐작이다
```

### 수사로 앞의 것을 가리키지 않는다 (2026-09-20 저자 지시)

저자가 `그 넷을 하나씩 들여다보기로 했다`를 **`문제를 하나씩`**으로, `화이트보드에 적어 둔 넷`을
**`화이트보드에 적어 둔 문제`**로 고쳤다. **가리킬 대상에 이름이 있으면 수사가 아니라 그
이름으로 부른다.** 수사는 셀 때만 쓴다.

| ✕ 수사가 지시어 노릇 | ✓ 이름으로 |
|---|---|
| `그 넷을 하나씩 들여다보기로 했다` | `문제를 하나씩 들여다보기로 했다` |
| `화이트보드에 적어 둔 넷 가운데 ④가` | `화이트보드에 적어 둔 문제 가운데 ④가` |
| `모델만 바꾸면 넷이 한꺼번에 해결된다` | `모델만 바꾸면 네 문제가 한꺼번에 해결된다` |

**세는 자리는 그대로 둔다** — `표본은 여덟이 아니라 넷이다` · `기대하는 ID는 R01–R04 넷이고` ·
`큐에 자리가 있던 넷만 들어가고`. 여기서 넷은 개수 그 자체지 무언가를 가리키는 말이 아니다.

§10(개수를 이름에 박아 넣지 않는다)과 짝이다. **개수는 셀 때만 쓰고, 가리킬 때는 이름을 쓴다.**

**바로 위 그림을 수사로 가리키는 자리가 제일 안 보인다 (2026-09-21).** `개발팀은 답을 정하는
이 여덟 가지를 묶어 release-a라고 불렀다`에서 여덟은 바로 위 그림에 든 항목 수다. 그림을 안 본
독자에게는 가리킬 것이 없고, 본 독자에게도 개수는 정보가 아니다. **그림이 든 것을 세지 말고
양 끝을 이름으로 불러 범위를 보인다** — `모델 리비전부터 권한 상태까지`.

**`여기(서)`는 이 절에 처음부터 있었는데 2026-09-21에 여섯 곳이 남아 있었다.** 규칙은 있고
검사기에는 없던 갈래다(§23). 고치면 대개 문장이 짧아진다 — `여기서 쓰는 모델` → `예제가 쓰는 모델`,
`여기 들어 있지 않다` → `크레딧에 넣지 않았다`. `여기까지만 본다`처럼 범위의 끝을 말하는 자리는 정상이다.

### 한 장에서 같은 수사가 여러 대상을 가리키지 않게 한다 (2026-09-20)

『AI 엔지니어링』 2장에서 `넷`이 세 가지를 가리키고 있었다 — 화이트보드에 적은 **네 가지 문제**,
`FourConditions` 그림의 **네 조건**, 환각의 **네 갈래**. 셋 다 `넷`이라 읽는 쪽이 매번 어느
넷인지 되짚어야 했다. **하나만 맨 수사로 남기고 나머지는 분류사를 붙여 이름으로 부른다.**

| ✕ | ✓ |
|---|---|
| `넷을 합쳐야 수치를 잘 생성하는 모델과 ~가 갈린다` | `네 조건을 합쳐야 ~` |
| `한 단어로 묶지 않고 넷으로 나눠 기록한다` | `한 단어로 묶지 않고 네 갈래로 나눠 기록한다` |

## 20. 주어와 서술어 — 넘기기 전 체크리스트

- **주어 없는 서술을 만들지 않는다** — `나머지는 밖에 둔다`(누가 두는가) → `기억장치에 남는다`
- **무생물을 주어로 세우고 사람의 동작 동사를 붙이지 않는다** — `버스가 나가서 닿는다`
- **주술을 맞춘다** — `컴퓨터는 ~ 돌고 ~ 들어간다` ✕ → `컴퓨터는 ~ 돌린다` 또는 주어를 나눈다
- **피동을 남용하지 않는다** — `설명되지 않는다`, `도출된다` → 능동으로
- 대조절의 시제를 맞추고, 대조에는 `사실`을 넣는다
- **동작의 상대(`~에게`)를 빼놓지 않는다** — 주는 동사·시키는 동사·요구하는 동사는
  받는 쪽이 있어야 문장이 선다

**네 번째 물음을 더한다 (2026-09-20).** 저자가 1장을 읽으며 세 문장을 같은 이유로 짚었다.
**이 동작에 상대가 있는가. 있다면 문장에 적혀 있는가.**

| ✕ | ✓ | 빠진 것 |
|---|---|---|
| `그래서 답변과 함께 근거를 요구한다` | `그래서 개발팀은 봇에게 답만 받지 않고 … 함께 받기로 했다` | 요구하는 쪽과 받는 쪽이 둘 다 없다 |
| `“육아휴직 …?”에 조건 세 줄을 덧붙여 답했다` | `직원이 “육아휴직 …?”라고 묻자 봇이 나온다고 답하면서 지급 조건 세 줄을 덧붙였다` | 물은 사람, 답한 쪽, **봇이 나온다고 답했다는 사실 자체** |
| `개발팀은 데모가 왜 맞혔는지부터 확인했다` | `개발팀은 담당자가 물었을 때 봇이 무엇을 보고 답한 것인지부터 짚어 봤다` | 맞힌 것은 사람이 하는 일이고, 정작 본 것은 `왜`가 아니라 `무엇을 보고`였다 |
| `일곱 줄은 … “어떤 상황에서 무엇을 해야 하는가”로 적혀 있다` | `개발팀은 일곱 줄을 하나같이 … 로 썼다` | 적은 사람. 저자가 **“일곱 줄을 주어로 안 쓰는 게 자연스러워”**라고 짚었다 |
| `첫 주가 끝나고 … 담당자는 그대로 쓰기로 했고, 전 직원 공개는 … 미뤘다` | `… 담당자만 그대로 쓰기로 하고, 나머지 직원에게는 준비가 끝난 뒤에 다시 열기로 했다` | `-고`로 이으면서 주어가 개발팀 → 담당자로 갈려, 담당자가 공개를 미룬 것처럼 읽혔다 |

셋째 줄이 특히 중요하다. **문장이 바로 다음에 올 것을 가리키지 않으면 고칠 자리다** —
그 아래가 프롬프트 블록인데 문장은 `왜 맞혔는지`를 묻고 있었다.

**이 목록은 자동화가 안 된다.** 한때 `check-prose.py`에 정규식을 넣었다가 오탐만 내서 뺐다
(`그런 문서가 있다는 사실조차 알리지 않는다`의 `문서가`를 주어로 잡았다). 그래서 **원고를
넘기기 전에 손으로 한 번 돌린다.** 문단마다 문장을 짚으며 묻는다.

1. 이 문장의 주어가 무엇인가. 사람인가, 물건인가, 명사절인가
2. 물건이나 명사절이면 — 그 일을 실제로 한 사람이나 시스템이 누구인가
3. 서술어가 그 주어가 할 수 있는 동작인가 (`화면이 내보낸다` ✕ · `화면이 보여 준다` ✓)

**`check-prose.py`가 조용한 것은 통과가 아니다.** 그 검사기는 낱말 패턴만 본다.
2026-09-19에 장 끝 문단 열일곱 개를 쓰고 검사기가 깨끗하다는 이유로 넘겼다가 여섯 곳을
지적받았다(§7). 검사기를 돌린 뒤에 **이 세 물음을 따로 돌린다.**

## 22. 넘기기 전 grep

**2026-09-19에 이 목록을 18개 장에 전부 돌려 좁혔다.** 넓은 채로 두면 오탐에 묻혀 아무도 안 본다.
아래가 좁힌 판이고, 괄호 안이 좁힌 이유다. 이 판으로 돌리면 이 원고는 **실제 위반 0**이다.

```bash
f=<파일>

# 영어 구조 직역
#   `이는 `를 문두·문장부호 뒤로 묶었다 — `보이는` · `줄이는` · `붙이는`을 다 잡았다
grep -nE "가진다|가지는데|위치한|위치하고|를 통하?[여어]|도출|총 [0-9]|(^|[.[:space:]])이는 " $f
#   `[가-힣]라는 [가-힣]`를 뺐다 — `만들어 달라는 요청` · `30만 원이라는 숫자`가 전부 걸린다
grep -nE "것이다|는 것은 [^.]{0,30}이다|인 것은|인 만큼|[가-힣]이며 " $f

# 만들어 쓴 연어 · 세다 · 얼버무리기
#   `센다`·`세는`을 분류 문맥으로 묶었다 — **토큰을 센다는 §4가 정한 옳은 말이다**
grep -nE "(갈래|가지|종류|개로|층으)로 (세|셀|센)|잇는|같은 것들|상대로|붙는다|붙이기|대체로|대개|보통 |편이다|셈이다" $f

# 피동·진행형 직역
grep -nE "입장에서|되어졌|만들어[진졌]|놓여 ?있|여겨[진졌]|보여진|설명되" $f

# 에두른 부정 · 에두른 명사 (§13)
grep -nE "지도 않았|[가-힣] 것도 없|[가-힣] 차례다|의 시작이다|대기가 어려" $f

# `A와 B는 다르다` (SKILL.md) — 넓게 잡고 눈으로 고른다
grep -nE "다르[다고며지]|서로 다른|다른 [가-힣]{1,8}[이인]|별개|무관하|뜻하지 않|보장하지 않" $f

# em dash · 짧은 부정 · most of
#   `안 `에 앞 경계를 붙였다 — **보안 · 제안 · 방안 안쪽까지 잡고 있었다**
grep -n "—" $f
grep -nE "(^|[[:space:](])안 [가-힣]" $f
grep -nE "대부분의 [가-힣]+(에서|은|는|이|가)" $f
```

grep으로 안 잡히는 것은 눈으로 본다. 문장마다 **주어가 사람인지 사물인지** 보고,
사물이 주어인데 사람이 하는 동작 동사가 붙어 있으면 고친다.

**고치려다 지우게 되는 경우가 많다.** 어색한 문장이 앞 문단이나 아래 표를 한 번 더 말하는 것뿐이면
표현을 바꾸지 말고 지운다.

## 23. 원고가 원고를 가리키지 않는다

저자가 「네 번의 실패와 그 뒤에 붙인 단계를 정리하면 일곱 줄이 된다」를 두고 물었다.
**"보통 소설에서 이렇게 말을 하나?"** 화자가 사건이 아니라 자기가 방금 쓴 원고를 가리키는 자리다.

2026-09-20에 23개 파일을 다중 에이전트로 전수 조사하면서 같은 갈래가 다섯 곳 더 나왔다.
**한 곳을 고쳐도 같은 손버릇이 파일 전체에 남는다**는 것이 이 표의 요점이다.

| ✕ | ✓ | 어디 |
|---|---|---|
| `두 문장은 동시에 참이다` | 모순처럼 들리지만 둘 다 그때 실제로 일어난 일이었다 | 06-operations/01-evaluation |
| `이 표는 모든 공격의 목록이 아니라 지켜야 할 조건의 출발점이다` | 개발팀은 공격을 다 적는 대신 어느 공격에서나 서버가 지킬 조건만 적었다 | 05-trust/02-security |
| `이 장이 확인한 범위는 …다` | 개발팀이 이 서버에서 확인한 것은 …까지다 | 06-operations/02-operations |
| `위 예제의 대기는 네트워크 성능 측정이 아니다` | (지운다 — 바로 위 코드 주석이 이미 적어 뒀다) | 07-appendices/01-python |
| `이 책이 남기려는 능력은 …이다` | 개발팀이 이 봇을 만들며 얻은 것은 … | 06-operations/03-final-project |
| `이 구분이 책 전체의 토대다` | (지운다 — 바로 뒤 `그래서` 문장이 이미 그 무게를 진다) | 01-foundations/01-document-assistant |
| `이 프로젝트는 최종 답변 캐시를 두지 않았고` | 개발팀은 최종 답변 캐시를 아직 두지 않았다 | 06-operations/02-operations |
| `토큰은 … 원고·커밋·로그에 붙이지 않는다` | 토큰은 … 커밋이나 로그에 남기지 않는다 | 06-operations/02-operations |

**저자가 읽다가 직접 짚은 두 곳이 여기 있다.** 「이 구분이 책 전체의 토대다」와
「무엇보다 그 링크를 몇 번이고 다시 보내던 담당자가 그 자리에 있었다」 — **둘 다 1장이고,
에이전트 두 명과 반론자 하나가 그 장에서 15건을 확정하고도 놓쳤다.** 앞 문장은 원고가 자기
무게를 선언하는 말이고, 뒤 문장은 「있었다」로 끝나 **그래서 어떻게 됐는지가 없다**(§14).
기계 검사도 다중 에이전트도 이 둘을 못 봤다 — **처음부터 끝까지 읽는 사람만 걸러 낸다.**

**`예제`와 `목록`은 이 갈래가 아니다.** 독자가 실제로 내려받아 돌리는 물건이라 가리키는 것이
정상이다 — 부록 D의 「아래 목록은 그날 실제로 깔려 있던 버전으로 읽는다」가 옳은 용법이다.
`check-book.py`의 「원고 자기 언급」 정규식에서 둘을 뺀 이유가 이것이다.

### 같은 조사에서 검사기가 놓친 세 갈래

**적힌 규칙보다 검사기의 그물이 먹는다.** 규칙은 있었는데 정규식이 좁아 빠져나간 자리다.

| 갈래 | 왜 빠져나갔나 | 넓힌 뒤 |
|---|---|---|
| have 직역 | 가진다·가지는데만 봤다 — `각 행은 …을 갖는다` · `시작·종료와 관계를 갖는 작업 구간`이 통과했다 | `[을를]\s*갖는`·`[을를]\s*갖고 있` 추가 |
| 만든 복합어 (~ 경계) | 목록에 책임·신뢰·호출·생성·시스템·접근·실행·서비스만 있었다 — `서버 경계` · `데이터 경계` · `결과 경계` · `교체 경계`가 통과했다 | 서버·데이터·구현·결과·교체 추가 |
| 봇 반말 | 명령형(`올려 줘`)만 봤다 — `우리 회사는 매월 50만 원까지 지원한다고 들었어`가 통과했다 | `했어`·`들었어`·`맞아`·`같아`·`거든`·`잖아` + 닫는 따옴표 추가 |

**2026-09-21에 세 갈래가 더 나왔다.** 같은 구조라 이어 적는다.
**첫 열은 갈래 이름이라 백틱을 두르지 않는다** — 두르면 `check-rules.py`가 그 이름을 원고에서
찾는 규칙으로 만드는데, `조건이 깨지다`는 원고에 그대로 나올 리 없는 분류명이라 검사가 헛돈다.
이 실수를 세 번째로 했다.

| 갈래 | 왜 빠져나갔나 |
|---|---|
| 조건이 깨지다 | 그물이 `(규칙\|조건\|요구사항)[을를이가]\s*깨`라 조사와 `깨` 사이에 말이 끼면 샌다 — `하나라도 깨지면`(주어가 앞 칸에 있다) · `R1–R7을 하나씩 깨뜨리는`(`하나씩`이 끼었다). 본문은 이미 `건드린다`로 고쳐 놓고 **부록만 남아 있었다** |
| 여기(서) | §19에 적혀 있는데 검사기에 넣은 적이 없었다. 여섯 곳 |
| 1인칭 | 어느 검사에도 없었다. 아래 §25 |

### `이 장은` · `이 책은`이 주어로 동작한다 (2026-09-21)

`이 장은 SDK를 설치해 동적 실행을 하지 않았고` · `이 책은 내려받을 수 있는 가중치를 ~라고 부르고`.
설치하지 않은 것은 개발팀이고 부르는 것도 사람이다. **`이 책의 구현` · `이 책에서는` · `이 책의
확인 범위`처럼 범위를 한정하는 꼴은 정상이다.** 가르는 것은 조사다 — **`은/이`가 붙어 동작을 끌면
고치고, `의`나 `에서는`로 범위만 말하면 둔다.**

`에 대한`을 놓쳤던 것과 같은 구조다(§15). **검사가 조용한 것은 통과가 아니다** — 이 세 갈래는
전부 §1·§8·SKILL.md §7이 이미 금지한 것이었고, 빠진 것은 규칙이 아니라 그물코였다.

## 24. 숫자와 이름은 장을 가로질러 맞춘다

**한 장 안에서는 멀쩡한데 장을 나란히 놓으면 어긋나는 갈래다.** 2026-09-20에 저자가 읽다가
두 건을 잡아냈고, 둘 다 기계 검사와 다중 에이전트 조사를 모두 통과한 상태였다.

| 무엇 | 한쪽 | 다른 쪽 | 어떻게 정했나 |
|---|---|---|---|
| 데모가 붙이던 문서 수 | 1장 `문서 세 개` | 3부 `사내 규정이 다섯 건일 때는` | 3부의 `다섯 건 → 200건`이 임베딩 장 전체를 끌고 가므로 그쪽이 기준 |
| 첫 실패 날짜 | 본문 `9월 2일` | 그림 `9/5 질문` | **이야기가 기준이다.** 그림을 9/2로 고쳤다 |

### 넘기기 전에 이 셋을 맞춰 본다

1. **장을 가로지르는 숫자.** 금액 · 건수 · 횟수 · 줄 수. 『AI 엔지니어링』은
   `20만 원` · `30만 원` · `다섯 건` · `200건` · `열한 번` · `일곱 줄` · `네 가지`가 그것이다.
   한 곳을 고치면 나머지를 전부 grep한다.
2. **본문과 그림.** `check-book.py`의 「본문에 없는 날짜가 그림에 있다」가 날짜만 자동으로 잡는다.
   금액·건수는 아직 눈으로 본다. 그림에만 있어도 되는 값은 그 스크립트의 `DIAG_DATE_OK`에
   **이유와 함께** 적는다.
3. **같은 것을 부르는 이름.** `최소 서버` · `작은 HTTP 서버` · `현재 HTTP 예제`가 한 장에서
   같은 `book_service.py`를 가리키고 있었다. 파일 이름이 있으면 파일 이름으로 부른다.

**한 곳을 지적받으면 파일이 아니라 책 전체를 훑는다** (SKILL.md §1은 파일 전체라고 적었는데,
숫자는 그 단위가 책이다).

### 그림은 보이는 글자만 고치면 절반이다 (2026-09-21)

2026-09-20에 `AnswerStates`의 `<text>` 제목을 `다섯 가지 답변 상태`로 고쳤는데, 같은 파일의
**주석과 aria-label은 `응답의 다섯 상태` 그대로였다.** aria-label은 화면 낭독기가 읽는 사용자용
문장이라 안 고치면 뜻이 어긋난 채로 나간다. 게다가 이 책에서 `응답`은 HTTP·제공자 응답이고
봇이 직원에게 주는 것은 `답변`이라 낱말까지 틀린 자리였다.
**그림을 고치면 `<text>` · 주석 · aria-label 셋을 같이 본다.**

## 25. 화자는 이야기 밖에 선다

이 책의 화자는 한울연구소 사람들을 3인칭으로 본다. 그런데 설명 문단에서 **`우리`가 슬쩍 들어오는
자리**가 있다 — `우리 요구사항과 맞춰 본다` · `그 필터가 우리 정책대로 걸리는지` · `우리 질문 집합으로
다시 평가한다` · `우리 조직에 지금 적용되는 규정`. 2026-09-21에 다섯 곳이 나왔고 전부 원칙을 말하는
문단이었다.

**서사가 3인칭인데 설명만 1인칭이면 한 책에 목소리가 둘이다.** 게다가 `우리`가 개발팀인지 독자인지
한울연구소인지가 자리마다 달랐다. 고치는 길은 셋이다.

- 행위자가 분명하면 이름으로 — `우리 요구사항` → `봇이 지켜야 할 요구사항`
- 서비스를 가리키면 서비스로 — `우리 정책` → `이 서비스의 정책`
- 아무것도 안 가리키면 뺀다 — `우리 조직에 지금 적용되는 규정` → `지금 적용되는 규정`

**따옴표 안은 등장인물의 말이라 그대로 둔다** — `“우리 회사는 매월 50만 원까지 지원한다고
들었는데요”`는 직원이 한 말이다. `내가` · `저희`도 같은 갈래다.

### 값을 주어로 세우고 `알려 주다`를 붙이지 않는다 (2026-09-21 저자 지시)

저자가 `HTTP 200은 그중 어느 쪽인지 알려 주지 않는다`를 두고 **번역투**라고 했다.
*doesn't tell you which*를 그대로 옮긴 자리다. 숫자·점수·코드는 말하는 주체가 아니다.

**도구격 `~로는`으로 내리고 아는 쪽을 사람으로 돌린다.** `200이라는 숫자 하나로는 그중 어느 쪽인지
가려낼 수 없다` · `점수로는 두 문장이 얼마나 가까운지까지만 알 수 있다` · `클릭 수로는 사용자가 무엇을
눌렀는지까지만 알 수 있다`. 한 곳을 고치고 책 전체에서 넷을 더 찾았다.

**`보여 주다`까지 밀지 않는다.** `예시가 처리의 형태를 보여 준다` · `화면에 초안을 보여 준다`는
국어에 원래 있는 짝이다. 걸리는 것은 **값이 주어일 때의 `알려 주다` · `말해 주다`**다.
같은 문장에 붙어 있던 `무엇이 돌아왔는지 먼저 읽어야 한다`도 함께 걸렸다 —
**주어 없는 당위(`~해야 한다`)는 동사 종결로 내린다**(`돌아온 것을 먼저 읽고 나서 화면에 뿌린다`).
