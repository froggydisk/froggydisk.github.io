# 책 한 장 쓰기

`src/content/book/<책>/NN-<부>/NN-<장>.md(x)`에 장을 쓰거나 고칠 때의 규칙이다.

**이 스킬의 구성**

- `SKILL.md` (이 파일) — 책의 목소리, 구성, 작업 절차
- `references/korean.md` — 실제 교정에서 걸러낸 어색한 한국어 목록. **원고를 넘기기 전에 반드시 훑는다**

**같이 보는 것**

| 무엇 | 어디 |
|---|---|
| 경로·URL 규칙, `book.yaml`, 표 첫 열 폭, 이 레이아웃의 함정 | `CLAUDE.md` §7 온라인 책 |
| SVG 다이어그램 규격 (viewBox·색 토큰·겹침 검사) | `.claude/skills/blog-post/references/diagrams.md` |
| 한국어 문체 일반 (비유 금지, 문장 길이, 관형절) | `.claude/skills/blog-post/SKILL.md` §1~3 |

블로그 스킬의 `## ▍제목` 접두어와 커버 이미지 규칙은 책에 적용하지 않는다.

## 1. 책의 목소리 — 문제집이 아니다

원본이 기술사 답안 노트라도, 책은 **그 주제를 설명하는 글**이지 답안 쓰는 법을 알려주는 글이 아니다.
아래는 전부 실제로 썼다가 지운 것들이다.

### 쓰지 말 것

| 종류 | 실제로 썼던 문장 |
|---|---|
| 답안 작성법 | `기술요소 열은 채워 넣는 편이 낫다` · `그림과 표 중 하나만 넣을 수 있으면 그림을 택한다` · `최근 기술을 얼마나 붙이느냐로 답안의 밀도가 갈린다` · `한 면을 채우지 못한다` |
| 문항 번호·페이지 | `문항 1의 답안 배분` · `3항에서 이 이름들을 다시 쓰게 된다` · `여기까지가 문항 1(p.18)과 2(p.20)다` |
| 로드맵 | `이 장은 하드웨어와 소프트웨어, 펌웨어에서 시작해 ~까지 다룬다` · `순서는 ~가 먼저이고 그다음이 ~` · `앞에서 나눈 순서를 그대로 두면 ~ 세 갈래로 갈린다` |
| 앞뒤 안내 | `기술요소 열의 이름들은 뒤의 발전 방향에서 다시 나온다` |
| 표를 가리키는 말 | `표 밖에도 적을 것이 있다` · `집적도 줄 끝에는` · `방향 열을 빼면 세 줄이 똑같아 보인다` |
| 인용문 앞 해설 | `컴퓨터의 정의는 이 한 문장에 다 들어 있다` · `컴퓨터의 두뇌라고 부르는 만큼 하는 일이 넓다` |
| 앞 문단 재정리 | `어떻게 나누느냐에 따라 같은 부품이 다른 갈래에 들어간다` (앞 두 문장이 이미 말한 것) |
| 수사적 틀 | `구성요소는 다섯인데 이름은 셋뿐이다` (X인데 Y뿐이다) · `세 갈래 모두 ~ 이야기인데` |

**로드맵 문장은 소제목이 이미 한다.** `## 발전 방향` 아래 `### 장치별 변화` · `### 시스템 지표` · `### 인터페이스 변화`가
있으면 "세 갈래로 나뉜다"고 미리 말할 필요가 없다.

**인용문 앞의 도입 해설도 대개 필요 없다.** 문단 뒤에 인용문이 바로 와도 읽힌다.

### 지우는 것이 고치는 것보다 나은 경우

문장이 어색해서 고치려다 보면, 그 문장이 하는 일이 **앞 문단이나 아래 표를 한 번 더 말하는 것**뿐인 때가 많다.
그러면 표현을 바꾸지 말고 지운다. 실제 교정에서 지운 문장의 절반이 이 경우였다.

### 한 곳을 지적받으면 파일 전체를 훑는다

**이 작업에서 가장 자주 반복한 실패다.** 한 문장을 고쳐서 넘기면 같은 표현이 다른 절에 그대로 남아 있어
바로 다시 지적받는다. `센다`는 세 곳, `붙는다`는 네 곳, `~를 가진다`는 두 곳에 있었다.

지적받은 표현을 고쳤으면 **그 자리에서 grep으로 같은 계열을 전부 찾아 한 번에 고친다.**
표 안과 그림 라벨, frontmatter `description`까지 본다. 본문만 고치고 표를 빼먹는 일이 잦다.
정상 용례가 섞여 있으면(`보드에 붙는다` ✓) 남기고, 왜 남겼는지 한 줄로 알린다.

### 이 목소리로 쓴 개요의 예

> 컴퓨터는 사용자, 응용 프로그램, 운영체제, 펌웨어, 하드웨어로 구성된다. 하드웨어는 다시 입력·기억·연산·제어·출력
> 다섯 가지로 나뉜다. 여기서 연산과 제어를 담당하는 부분은 한 칩에 들어가는데, 우리는 이 칩을 CPU라고 부른다.

사실 세 문장으로 끝난다. 무엇을 다룰지 예고하지 않는다.

## 2. 구성

### 개요와 본문의 순서를 맞춘다

개요에서 하드웨어를 먼저 쪼개놓고 본문은 층부터 시작하면 독자가 두 번 방향을 바꾼다.
개요의 문장 순서가 곧 `##` 소제목 순서여야 한다.

### 원본이 문항 여러 개면 축을 다시 잡는다

문항 세 개를 그대로 이어 붙이면 같은 내용이 세 번 나뉜 것처럼 읽힌다.
문항 번호가 아니라 **주제 자체의 축**으로 다시 나눈다. 이 책에서는 밖에서 안으로 좁혀 들어가는 축을 썼다.

```
정의 → 하드웨어·소프트웨어·펌웨어(층) → 하드웨어의 구성요소(다섯) → CPU 안쪽 → 발전 방향
```

축을 다시 잡으면 항목도 따라 옮겨야 한다. `메모리 컨트롤러 내장`은 원본에서 "시스템 발전"에 있었지만
장치별 변화(제어)로, `직렬 전송`·`I/O 전압`·`CXL`은 인터페이스로 옮겼다. 그러자 같은 항목이 두 표에
나오던 중복이 사라지고, 중복을 변명하던 문단도 같이 없어졌다.

### 소제목

**형제끼리 같은 꼴로 맞춘다.** 이 장의 `##` 다섯 개는 전부 명사구다.

```
## 컴퓨터의 정의
## 컴퓨터 시스템
## 하드웨어의 구성요소
## CPU
## 발전 방향
```

범위가 넓은 쪽에서 좁은 쪽으로 내려가고, 하나가 관형절이면 다섯 개가 다 어긋나 보인다.

| 고친 제목 | 무엇이 문제였나 |
|---|---|
| `소프트웨어가 차지하는 두 층` → `응용 프로그램과 운영체제` | 관형절 + 만든 연어(`차지하다`). 절 안에 있는 것을 그대로 부르면 된다 |
| `하드웨어와 소프트웨어, 펌웨어` → `컴퓨터 시스템` | 다섯 층 중 셋만 불러서 `사용자`가 빠졌다 |
| `정의와 자료 처리 과정` → `컴퓨터의 정의` | 둘을 나열한 제목. 하나로 덮을 수 있으면 하나로 |
| `하드웨어 안의 다섯 장치` → `하드웨어의 구성요소` | 수사 + 명사 어순 |
| `장치 안에서 달라지는 것` → `장치별 변화` | 관형절 + `것` |
| `시스템 전체를 재는 숫자` → `시스템 지표` | 관형절 |
| `펌웨어를 따로 세우는 이유` → `펌웨어가 따로 있는 이유` | 만든 연어(`따로 세우다`) |

**후보를 고를 때 겹침을 본다.**

- 상위 제목과 겹치면 버린다 — `소프트웨어의 두 층`은 상위가 `하드웨어와 소프트웨어, 펌웨어`였을 때 겹쳤다
- 다른 절과 겹쳐도 버린다 — `컴퓨터가 하는 일`은 `### CPU의 동작`과 같은 말로 읽힌다

**제목을 바꾸면 frontmatter `description`도 같이 고친다.** 실제로 `세 갈래 버스`를 `세 종류의 버스`로
바꾼 뒤 description만 옛 이름으로 남아 있었다.

**절이 통째로 없어지는 경우가 있다.** `문항 1의 답안 배분` · `남은 문항` · `그림 셋의 차이`는
제목을 고칠 게 아니라 절 자체가 §1에서 금지한 것이었다.

### `###`을 쓴다

`##`만 15개 늘어놓지 말고 두 단으로 나눈다. TOC가 `h2, h3`를 다 잡고 h3를 들여쓴다
(`TOC.astro`, `editorial.css`의 `.toc-item.toc-h3`). **사이드바 목차는 `h2`가 5개 이상일 때만 뜬다**
(`TOC.astro`의 `threshold`). h3만 늘리다 h2가 4개가 되면 목차가 사라진다.

### 표와 그림

- 대응 관계(항목 ↔ 설명)는 표, 순서·방향·묶음은 그림
- 표 도입문이 표의 열 이름을 되풀이하면 지운다
- 표 헤더에 의문형을 쓰지 않는다 (`어디까지 왔나` ✕ → `방향` ✓)
- 표 헤더와 본문의 말을 맞춘다 (본문이 `네 부분`인데 헤더가 `갈래`면 어긋난다)
- 그림 안의 라벨과 본문 문장이 같은 말이면 하나를 지운다
- **그림을 새로 만들었으면 헤드리스로 렌더를 본다.** SVG는 겹쳐도 에러가 안 나서 빌드로는 못 잡는다.
  회전한 한글 라벨이 뒤집혀 나온 것을 이걸로 잡았다 (아래 §5). 회전 텍스트는 되도록 쓰지 않는다

## 3. 손으로 쓴 노트를 옮길 때

1. HEIC를 변환해 읽고, 안 읽히는 칸은 잘라서 다시 본다. `-c`는 높이·너비, `--cropOffset`은 위·왼쪽 순서다

   ```bash
   sips -s format jpeg -Z 2200 IMG_0000.HEIC --out page.jpg
   sips -c 1200 900 --cropOffset 300 1150 page.jpg --out crop.jpg   # 높이 1200 · 너비 900
   ```
2. **표의 병합 셀을 놓치지 않는다.** 세로로 이어진 `구분` 열이 여러 행을 묶고 있는 경우가 많다
3. **틀린 것은 고쳐 적는다.** 원본이 `SSI → LSI`로 건너뛰면 `MSI`를 넣고, `Z(zeta)B`는 `ZB(zetta)`로 고친다.
   다만 원본에만 있는 이름(`VVLSI`)은 살리되 "굳은 이름은 아니다"라고 밝힌다
4. **원본을 언급하지 않는다.** `원서가 ~라고 적어두었다` ✕ → `~라고 부르기도 한다` ✓
5. 옮긴 뒤 용어 누락을 grep으로 확인한다 (아래 §5)

## 4. 어색한 한국어

**판단 기준은 뜻이 통하는지가 아니라 그 분야에서 실제로 그렇게 쓰는지다.**
`프로토콜로 잇는다` · `선을 탄다` · `따로 세운다`는 다 뜻이 통하지만 아무도 그렇게 쓰지 않는다.
확신이 없으면 동사를 하나로 줄이고 흔한 쪽을 택한다.

여섯 갈래로 걸린다. **초고를 넘기기 전에 `references/korean.md`를 연다** — 갈래마다 실제 교정 목록과
grep이 있다.

| 갈래 | 예 |
|---|---|
| 영어 구조 직역 | `~를 가진다` · `~에 위치하다` · `~를 통해 ~ 이는 ~ 도출된다` |
| 수사 + 명사 어순 | `다섯 장치` (분류사가 빠졌다) |
| 만들어 쓴 연어 | `잇는다` · `선을 탄다` · `붙는다` · `따로 세운다` |
| `세다` | `셀 때` · `세는 방식` |
| 얼버무리기 | `대체로 다 들어간다` · `총 5개` |
| 흐린 지시 | `여기` · `밖` · `앞의 둘` |

## 5. 검증

```bash
npm run build

f=src/content/book/<책>/<부>/<장>.mdx

# 문제집 목소리 (이 스킬에만 있는 검사)

# 소제목이 형제끼리 같은 꼴인지 · h2가 5개 이상인지
grep -nE "^#{2,3} " $f
```

```bash
# 단문 나열로 끊긴 문단 · 번역투 (18개 장 전체는 인자 없이)
python3 .claude/skills/book-chapter/scripts/check-prose.py $f
```

```bash
# 한국어 코퍼스 기준 계측 (vendored · scripts/vendor/humanize-kr/NOTICE.md)
M=.claude/skills/book-chapter/scripts/vendor/humanize-kr/metrics_v2.py
python3 $M --input <평문.txt> --genre essay      # risk_band · T1~T8 간섭 · ending_comma_rate
```

평문은 frontmatter·코드블록·JSX·표를 걷어낸 산문만 넣는다. 마크업이 섞이면 수치가 망가진다.

`risk_band`가 `low`이고 `T1_inanimate_subject_rate`·`by_passive_count`·`pronoun_density`가
0이면 통과다. `ending_comma_rate`의 z가 +3을 넘으면 §3-6으로 간다.

어색한 한국어 grep은 `references/korean.md` §8에 있다. 여기 옮겨 적지 않는다.
**단문 나열은 이 책에서 가장 여러 번 지적받은 항목이라 `check-prose.py`를 매번 돌린다** (§3-2).

**grep 결과는 오탐을 걸러 본다.** `붙는다`는 `보드에 붙는다`(실장)가, `흐려진다`는 `구분이 흐려진다`가
정상이다. `안 [가-힣]`에는 `답안 배분`이 걸린다. 결과가 0이어야 하는 검사가 아니라, 한 줄씩 눈으로 보는 목록이다.

**손글씨 노트를 옮겼다면 용어 누락을 확인한다.** 옮기면서 한 줄이 통째로 빠지는 일이 있다.

```bash
for t in "BIOS" "MTBF" "Data Skew" "CXL" ...; do grep -q "$t" $f || echo "누락: $t"; done
```

**그림을 새로 만들었거나 고쳤다면 렌더를 본다.** dist의 HTML에서 `<svg>`를 aria-label로 골라 뽑고,
`editorial.css` 토큰 값을 인라인한 임시 HTML에 넣어 `--screenshot`으로 찍는다.
첫 `<svg>`는 네비게이션 아이콘이니 제목이나 aria-label로 고른다.

```bash
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless --disable-gpu \
  --window-size=700,400 --force-device-scale-factor=2 --screenshot=out.png tmp.html
```

**문장 길이** — 평균 31~42자. 이 아래면 단문 나열, 크게 웃돌면 명사구를 쌓은 것이다.
연속 단문 네 개가 한 문단 안에 있으면 연결어미로 잇는다.

```bash
python3 - <<'EOF'
import re
p = 'src/content/book/<책>/<부>/<장>.mdx'
body = open(p, encoding='utf-8').read().split('---\n', 2)[2]
prose = [l.strip() for l in body.split('\n')
         if l.strip() and not l.strip().startswith(('#','|','-','<','import','*','!','>','{'))]
sents = []
for l in prose:
    l = re.sub(r'\*\*|`|\[.*?\]\(.*?\)', '', l)
    sents += [x.strip() for x in re.split(r'(?<=[.?])\s+', l) if x.strip()]
lens = sorted(len(x) for x in sents)
print(f'{len(lens)}문장 · 평균 {sum(lens)//len(lens)}자 · 중간값 {lens[len(lens)//2]}자')
run = []
for x in sents:
    run = run + [x] if len(x) < 45 else []
    if len(run) >= 4: print('연속 단문:', ' / '.join(run))
EOF
```

**라우트를 늘렸다면** `src/pages/sitemap.xml.ts`도 고친다. `dist/sitemap.xml`과 `dist/sitemap-0.xml`의
URL 개수가 같아야 한다 (`CLAUDE.md` §5).

## 6. 편집

MDX 본문은 **python 치환 + assertion**으로 고친다. sed는 한국어·특수문자에서 위험하다.

```python
def rep(a, b):
    global s
    assert s.count(a) == 1, repr(a[:45])   # 앵커가 유일한지 검증
    s = s.replace(a, b)
```

**사용자가 편집기에서 같은 파일을 고치고 있을 수 있다.** 앵커가 안 맞으면 파일이 바뀐 것이니
현재 내용을 다시 읽고 앵커를 새로 잡는다. 사용자가 직접 고친 문장은 살린다. 사용자 수정과 내 수정이
겹쳤으면 어느 쪽을 남겼는지 알린다.

**명령 결과를 못 봤으면 적용됐다고 가정하지 않는다.** 파일을 다시 읽어 확인하고 나서 다음 수정을 한다.
되돌리라는 요청이 왔는데 이미 적용돼 있는 상태일 수 있다.

## 7. 『개발자를 위한 AI 엔지니어링』 개작 규칙

`src/content/book/ai-engineering/`. 초고(2026-09-08)는 장마다 3,000단어에 그림이 없고 유보문이 문장 여섯 개마다 하나였다.
1장을 아래 규칙으로 다시 써서 1,000단어 · 그림 5장으로 만들었고, 나머지 장도 같은 규칙을 따른다.

- **독자는 ML 배경 없는 개발자다.** 코드는 남기되 핵심 대목만. 전체 구현은 `books/ai-engineering/examples/`에 있다고 한 줄로 가리킨다
- **절마다 한울연구소 장면으로 시작한다.** 원칙은 장면 뒤에. "교육비 한도를 20만 원이라고 답했다"가 먼저, "검색과 생성을 분리한다"는 그 다음
- **유보문은 절당 하나.** `않는다·아니다·단정·주장·가정·보장하지·뜻이 아니`가 100문장당 10을 넘으면 지운다 (초고는 13~25)
- **책이 만든 복합어를 쓰지 않는다.** `출력 계약·결과 계약·입력 계약·응답 계약·인용 계약·책임 경계·신뢰 경계·호출 경계·생성 경계·시스템 경계`.
  무엇을 검사하는지 이름으로 적는다 (`출력 계약을 지킨다` ✕ → `상태·답변·근거 세 필드가 다 있다` ✓)
- **장 사이 안내·검증 로그를 본문에서 뺀다.** `11장에서 다룬다` · `앞 장의` · `2026-09-08에 확인했다` · `실측하지 않았다` · `주장하지 않는다`.
  버전 고정은 부록 D, 검증 기록은 `books/ai-engineering/EDITORIAL.md`가 맡는다
- **절 번호를 붙이지 않는다.** `##`는 명사구 5개 이상. 사이드바 목차가 h2 5개부터 뜬다
- **봇이 사람에게 반말하게 두지 않는다.** 사람이 사람에게, 직원이 봇에게 모두 존댓말이다
  (`올려 줘` ✕ → `올려 주세요` ✓). 개발자가 자기 CLI에 넣는 테스트 인자만 예외이고,
  그것도 `experiments/*.json`에 기록된 문자열이면 손대지 않는다 — 책과 실행 기록이 어긋난다
- **장을 여는 장면은 끊지 말고 이어 쓴다.** 누가 왜 그 일을 시작했는지가 빠지면 전개가 튄다.
  1장의 도입은 기승전결로 놓았다: 반복되는 질문 → 개발팀에 부탁 → 오후의 데모가 잘 돎 →
  전사 도입 결정 → 첫 주에 네 번 깨짐. 마지막 박자는 장 끝에서 받는다
- **실습 절을 두지 않는다.** 이 책은 정보 전달이 목적이라 과제 목록이 들어갈 자리가 없다.
  2026-09-17에 18개 장의 `## 실습: …`을 전부 걷어냈다. 그 자리에 쓸 분량은 원리 설명에 쓴다 —
  토큰이 무엇인지, 어텐션이 무엇을 계산하는지, 대조 학습이 무엇을 당기고 미는지처럼
  **규칙 말고 기전(機轉)**이다. 초고가 규칙과 유보만 늘어놓고 그 규칙이 필요한 이유를 빼먹는 일이 잦다.
  시연 명령과 실행 결과는 남기되 본문 절 안에 둔다 (예: 5장의 `answer_demo.py` 출력 세 줄)
- **그림 3~5장.** 순서·방향·비교·시간은 그림, 대응은 표. 규격은 `diagrams.md`. 초고의 ASCII 도식은 전부 SVG로
- **식별자는 그대로 둔다.** `R1~R7`, `Q01~Q20`, 다섯 상태 이름(`answered` …), 문서 필드(`doc_id` …), 예제 파일 이름. 뒤 장과 코드가 참조한다
- **분량은 원문의 1/3~1/2.** 표·그림이 말하는 것을 본문이 다시 말하면 본문을 지운다
- **그러나 눌러 놓은 문장은 풀어 쓴다.** 위 규칙만 보고 줄이다 보면 처음 나오는 개념까지
  한 줄로 눌러서, 아는 사람만 읽히는 글이 된다. 2026-09-18에 그렇게 눌린 자리를 여러 번 지적받았다.

  **지울지 풀지는 한 가지로 가른다 — 되풀이인가, 처음 말하는 것인가.**

  | 되풀이 → 지운다 | 처음 말하는 것 → 푼다 |
  |---|---|
  | 앞 문단이 이미 한 말 | 그 장의 토대가 되는 문장 |
  | 표·그림의 라벨과 같은 말 | 규칙이 왜 필요한지의 기전 |
  | 소제목이 이미 예고한 것 | 독자가 직접 확인할 수 있는 절차 |

  ```
  ✕  교육비 규정은 어느 모델의 학습 자료에도 들어 있지 않고,
     모델은 방금 프롬프트에 붙여 준 두 문장을 읽고 답했을 뿐이다.     ← 장 전체의 토대가 한 줄에

  ✓  교육비 규정은 어느 모델의 학습 자료에도 들어 있지 않다. 한울연구소가 지어낸 회사라서
     그런 것만은 아니다. 실제 회사라도 사내 규정을 인터넷에 공개하지는 않는다. …

     확인하는 방법은 간단하다. 문서를 빼고 질문만 보내 보면 된다. 같은 모델에 같은 질문인데도
     30만 원이라는 숫자는 나올 수 없다. 그 숫자가 모델 안에 없기 때문이다.
  ```

  **규칙 두 개를 한 문장에 쉼표로 이어 붙이지 않는다**(`korean.md` §3-5)도 같은 이야기다.
  토큰·어텐션·대조 학습·BM25·LoRA·청킹·큐의 기전 설명도 전부 이 규칙으로 되살린 것이다
- **한 줄에 `~`가 두 개면 GFM 취소선이 된다.** `R1\~R7 … Q01\~Q20`처럼 이스케이프한다. 1장에서 실제로 걸렸다
- **파일은 `.mdx`로 바꾼다.** 슬러그는 제목이 크게 바뀔 때만 바꾼다 (책은 미공개라 URL 부담은 없다)
